# gonzalochale-saas-landing migration findings

## Summary
- Source: https://github.com/gonzalochale/saas-landing-template @ `7bc36b2a7ae905314c6b7fc95e0168ce5bf0db49`, Next.js 16.1.6 (App Router, React 19.2), Tailwind v4.2 (`@tailwindcss/postcss`, no `tailwind.config`), shadcn `new-york` / `neutral`, `tw-animate-css`. UI libs: Radix (accordion, dialog, dropdown-menu, tooltip, separator, slot), `@radix-ui/react-icons`, framer-motion 12, `@number-flow/react`, next-themes. No `public/` directory: the only assets are `app/favicon.ico` and `app/opengraph-image.png`.
- Demo: https://saas.gonzalochale.com
- Port: /tmp/bui-ports/gonzalochale-saas-landing (port 4410). Astro 7.3.5, bejamas 0.5.0, Tailwind 4.3.3, @data-slot/* 1.1.1.
- Fidelity verdict: **close with documented approximations**. Static layout matches the live demo to the pixel at 1440px and 390px: every section's top and height are identical, and the page height is the same (3655 / 4488 px). Light mode matches too. Motion is approximated, and the NumberFlow count-up is dropped.
- Effort hotspots:
  1. Restyling bejamas defaults back to shadcn new-york (Button radius/heights/padding/ghost hover, Card ring + `border-none`, Dialog/Dropdown/Tooltip surfaces).
  2. Inline `<script>` siblings emitted by bejamas components break `space-x-*`/`space-y-*` spacing.
  3. Getting scroll-driven CSS animations through Tailwind v4's Lightning CSS minifier (it folds `animation-timeline` into the `animation` shorthand, and Chrome then drops the whole declaration).

## Component mapping (shadcn/React → bejamas/Astro)
| Source | Port | Notes on API differences |
|---|---|---|
| `<Button asChild><Link/></Button>` | `<Button as="a" href>` | bejamas Button defaults differ from new-york: `rounded-lg` (vs `rounded-md`), `sm` = `h-8.5` (vs `h-8`), default `px-3` (vs `px-4`), `has-[>svg]:px-2` on sm (vs `px-2.5`), ghost hover `bg-secondary` (vs `bg-accent` / `dark:bg-accent/50`), and an extra `active:scale-98`. I overrode these per call site (`h-8 rounded-md px-3 hover:bg-accent …`). |
| `DialogTrigger asChild><Button/>` | `<Button data-slot="dialog-trigger">` inside `<Dialog>` | bejamas `asChild` renders a **wrapper `<div data-slot=…-trigger data-as-child>`**, and @data-slot has no as-child logic (no string match in `@data-slot/*/dist`). The div becomes the trigger and the button sits inside it. Passing `data-slot` straight to `Button` (the same thing `DropdownMenuTrigger` does internally) gives a single real button. |
| `DialogContent` (Radix, `bg-background border rounded-lg shadow-lg sm:max-w-lg gap-4`) | `DialogContent class="gap-4 rounded-lg border bg-background p-6 shadow-lg ring-0 sm:max-w-lg"`, `overlayClass="bg-black/50 supports-backdrop-filter:backdrop-blur-none"` | bejamas uses `ring-1 rounded-xl sm:max-w-md gap-6` and a `bg-black/10` overlay with blur. The close X opacity/size is adjusted with `[&>[data-slot=dialog-close]]:…`. `DialogTitle` defaults to `font-medium` with `cn-font-heading`; I added `text-lg font-semibold`. `DialogFooter` has no responsive `flex-col-reverse`, so I added it. |
| `DropdownMenu` + `DropdownMenuContent className="w-80"` | Same names; `align="center"` | Radix defaults `align` to `center`, bejamas to `start`. Without the prop the menu shifts ~100px. bejamas content uses `ring-1 rounded-lg` and the port restores `border rounded-md ring-0`. `DropdownMenuTrigger` takes Button props (`variant`, `size`). |
| `Tooltip/TooltipTrigger asChild/TooltipContent` (`bg-primary text-primary-foreground`) | `Tooltip` > `TooltipTrigger` (button) > `TooltipContent class="bg-primary text-primary-foreground rounded-md …"` | bejamas uses `bg-foreground text-background`. The arrow has no class prop, so it's recolored with `[&_[data-slot=tooltip-arrow]]:bg-primary`. No `TooltipProvider` is needed. |
| `Accordion type="multiple"` | `<Accordion multiple>` | Item `value` is required. bejamas `AccordionItem` lacks `last:border-b-0`. `AccordionTrigger` adds `border border-transparent` (+2px per row versus shadcn), so I added `border-0`. The trigger swaps two icons on open, while shadcn rotates one. Use the `icon` slot plus `group-aria-expanded/accordion-trigger:rotate-180`. |
| `Card`, `CardContent`, `CardFooter` | Same | bejamas Card: `ring-1 … border-none … border border-border shadow-lg overflow-hidden text-sm`. It has to be overridden with `ring-0 shadow-sm overflow-visible text-base border-solid` (see Bugs). |
| `Separator` | `Separator` | Same visual. |
| next-themes `ThemeSwitcher` (Button + `setTheme`) | bejamas `Toggle` (pressed = light) + a script that mirrors `toggle:change` onto `<html class>` / `localStorage.theme` | The Toggle owns the state. The script only reflects it (a derived display). `aria-pressed:bg-muted` is overridden to stay transparent. |
| framer-motion `AnimatePresence` mobile menu | `Collapsible` + `CollapsibleContent animation="slide"` | `--collapsible-panel-height` drives the height transition. The staggered item slide-in is a CSS keyframe keyed on `[data-state=open]`. |
| Testimonials `useState(showAll)` | `Collapsible` around the grid; trigger = `Button data-slot="collapsible-trigger"` | `group-data-[state=open]/collapsible:hidden` hides the trigger and the fade overlay once it's open. |

## Gaps in bejamas/ui (missing components, variants, props, primitives)
- **Close a collapsible panel when a link inside it is selected.** The source mobile menu calls `setIsMenuOpen(false)` on link click. `HamburgerMenu` has this behavior (in its own script), but its layout is fixed: 48px bar, brand left, trigger right, full-viewport absolute panel, `border-b`. That can't reproduce this navbar (trigger left, brand centered, theme toggle right, inline panel that pushes nothing and animates its height). I used plain `Collapsible`, so tapping "Pricing" in the open mobile menu scrolls the page but leaves the panel open. Candidate fix: a `data-close-on-link-click` option on `@data-slot/collapsible`, or HamburgerMenu slots/props for trigger position and an inline panel.
- **No "once" in-view reveal primitive.** framer `whileInView viewport={{ once: true }}` has no @data-slot equivalent. I used CSS `animation-timeline: view()`, which is scroll-position-bound rather than latched (it plays again in reverse if you scroll an element back below the fold).
- **No animated number primitive** (NumberFlow). The count-up was dropped.
- **No theme-switch component.** Every next-themes site needs one. `Toggle` + a tiny mirror script works, but a documented recipe or component would help (the docs app has none I could find in `apps/web/src`).
- **`asChild` is not real composition** (see the mapping table). It adds a wrapper div that becomes the interactive element.

## Bugs / issues in bejamas 0.5.0 or its CLI
- **Inline component `<script>` tags break sibling-spacing utilities.** Every interactive bejamas component (Toggle, Dialog, Collapsible, DropdownMenu, Tooltip, Accordion) renders its `<script>` in place, as the next sibling of the component root. In a parent with `space-x-*`/`space-y-*` (implemented with `:not(:last-child)` margins), the component root is no longer the last child and picks up a stray margin.
  - Repro 1: `<div class="flex items-center space-x-4"><Button/><ThemeSwitcher/></div>` with a Toggle inside ThemeSwitcher. Observed: the whole right-hand nav group shifted 16px left (Toggle at x=1276 vs 1292 in the source). Fix: `gap-4`.
  - Repro 2: `<div class="space-y-3"><Dialog>…</Dialog></div>`. Observed: the hero is 12px taller on mobile (538 vs 526). Fix: `<Dialog class="contents">`.
  - Expected: no layout effect. General rule: prefer `gap-*` over `space-*` around bejamas components.
- **Card has contradictory default classes.** The class string is `ring-1 … border-none … border border-border shadow-lg`. `border-none` and `border` are different tailwind-merge groups (style vs width), so both stay, and the computed border is `0px none`. Passing `class="border border-border"` or `border-2 border-primary` therefore shows **no border** (measured `bw=0px none`). You need `border-solid`. Card also defaults to `overflow-hidden`, which clips absolutely positioned badges such as the `-top-4` "Most Popular" pill (`overflow-visible` needed), and to `text-sm`.
- **CLI template pins `bejamas ^0.4.1`** in package.json (known, per brief). `bun add bejamas@0.5.0` fixed it. `init -b neutral` still ships a blue `--primary` (`oklch(0.4634 0.2647 264.76)`) in both `:root` and `.dark`, so the primary token must always be replaced.
- **Scroll lock + `scrollbar-gutter: stable` under Playwright** (low confidence, probably a test-environment artifact). Opening Dialog or DropdownMenu sets `overflow:hidden; scrollbar-gutter:stable` on `<html>`. In Playwright's Chromium, which launches with `--hide-scrollbars` (`innerWidth - clientWidth = 0`), this still reserves a ~15px gutter, so the page shifts ~7px left while the overlay is open. Radix (`react-remove-scroll`) shows no shift in the same harness. On real classic or overlay scrollbars it should be a no-op. Worth checking on Windows Chrome.

## Theming, fonts, assets
- **Cascade trap in the source CSS.** `app/globals.css` defines a custom palette (`--background:#131316`, `--card:#1c1c1c`, `--border:#202020`, …) inside `@layer base`, then the stock shadcn neutral `:root`/`.dark` blocks **unlayered**. Unlayered rules win, so the live demo renders plain shadcn neutral (computed `--background: lab(2.75%)` = `oklch(0.145 0 0)`, `--card` = `oklch(0.205 0 0)`). Only `--light` (`#5ba8ff` / `#016fee`, the hero glow) survives, because nothing overrides it. I verified this by reading computed custom properties on the live page. The port uses the effective values, adds `--light` + `--color-light`, and keeps bejamas-only tokens (`--destructive-foreground`). Lesson: read computed tokens from the demo rather than trusting the first block in globals.css.
- The body font is declared `font-family: Arial` in `@layer utilities`, but `geist.className` on `<body>` (unlayered next/font CSS) wins. Effective font: Geist. Ported with `fontProviders.google()` `name: "Geist"`, `weights: ["100 900"]`, as `--font-sans`; `--font-heading` = sans. No mono is used.
- Tailwind v4 → v4: no translation was needed (`bg-linear-to-b`, `max-w-(--breakpoint-xl)`, `h-150`, `rotate-35`, `supports-backdrop-filter:` all work in 4.3). `@custom-variant dark (&:is(.dark *))` is identical.
- Assets: `app/favicon.ico` → `public/favicon.ico`, and `app/opengraph-image.png` → `public/opengraph-image.png` (Next's file-convention OG image becomes an explicit `<meta property="og:image">`). Partner logos are inline SVGs copied from the source. The Tailwind logo's `id="gradient"` was renamed to avoid a global id collision.
- Icons: the source uses **@radix-ui/react-icons**, not lucide. I rendered the 13 used icons from `@radix-ui/react-icons@1.3.2` to static SVG (in a scratch dir) into `src/data/radix-icons.ts` + `RadixIcon.astro` (15×15 viewBox), to keep glyphs identical. lucide's `ChevronDown` is used only where shadcn's accordion itself uses lucide.

## Animation & third-party libraries
- framer-motion `initial/animate` (hero, glow) → CSS keyframes `.animate-enter-up` (0.6s, `translate: 0 20px` + opacity) and `.animate-enter-glow` (2s fade, 0.5s delay).
- framer-motion `whileInView once` (section headers, cards, stats, FAQ, footer, partner logos with `blur(3px)`) → `.animate-in-view` / `.animate-in-view-blur` with `animation-timeline: view(); animation-range: entry 0% entry 100%`. Two gotchas:
  1. **Lightning CSS (Tailwind v4's minifier) merges `animation` + `animation-timeline` into one shorthand** (`animation:.6s … both enter-up view()`), which Chrome rejects, so the animation silently disappears. Write longhands only (`animation-name`, `-timing-function`, `-fill-mode`, `-timeline`, `-range`) and leave out duration/delay, which keeps the minifier from rebuilding the shorthand. The same applies to the navbar's `scroll(root)` timeline.
  2. Use `animation-fill-mode: forwards`, **not `both`**. With `both`, every element below the fold sits at `opacity:0` until it enters, so full-page screenshots, print and no-scroll contexts show blank sections. With `forwards`, nothing applies before the range starts, and the jump to opacity 0 happens exactly at the viewport edge, where the user can't see it.
  - The per-item stagger delays (`delay: index * 0.1`) were dropped. Time-based delays don't map onto scroll timelines.
- Navbar `isScrolled` scroll listener → `@keyframes navbar-scrolled` on `animation-timeline: scroll(root); animation-range: 0 1px`, plus a `:has([data-slot=collapsible][data-state=open])` override for the "menu open" blur.
- Mobile menu `AnimatePresence` height/opacity → `CollapsibleContent animation="slide"` (height only, open only, because the root hides content with `display:none` on close, so there's no exit animation). Item x-slide stagger → keyframes with a `--delay` custom property. Hamburger rotate 90° → `group-data-[state=open]/collapsible:rotate-90`.
- `@number-flow/react` → dropped. Static final values, with a `py-[0.27em] md:py-[0.28em] leading-none inline-block` box matching `<number-flow-react>`'s measured height (46px / 56px), so the vertical rhythm stays identical.
- All motion is wrapped in `prefers-reduced-motion: no-preference`, except the navbar background, which is not motion.

## Next.js-specific translations
- `next/font/google` Geist → Astro fonts API (`BEJAMAS_ASTRO_FONTS`) + `<Font cssVariable="--font-sans" preload />`.
- `next-themes` (`attribute="class" defaultTheme="dark"`) → `<html class="dark" style="color-scheme: dark">` plus an inline head script that reads `localStorage.theme` (the same key next-themes uses), so there's no flash. The theme Toggle mirrors its state to the class and storage. The source's switcher always starts with a Moon icon (`useState(<MoonIcon/>)`), even after a reload in light mode. The port shows the icon for the actual theme (sun in light). That's a deliberate small deviation.
- `next/link` → `<a>`. `metadata` → `<title>`/`<meta>` in the layout. `app/opengraph-image.png` → explicit OG meta. `"use client"` components → static Astro components, with all lists rendered in frontmatter.
- The `isMobile` `matchMedia` effect in Testimonials became pure CSS (`max-md:` variants). That removes the hydration flash where the source briefly renders 6 cards on mobile.

- Geometry vs. live demo (Playwright, after scrolling through): **1440px**: nav buttons, every section's top and height, the stats boxes, the pricing cards (`208,2237,320,505` / popular `555,2230,330,520`, border widths 1px/2px) and FAQ rows (53px) are identical, and the page height is 3655 = 3655. **390px**: all sections identical, page height 4488 = 4488. Light mode (localStorage `theme=light`) also compared visually for hero and pricing: identical apart from the theme icon.
- Interactive checks (`.compare/interactions.mjs`): dropdown opens and closes on Escape; dialog opens and closes via X; tooltip shows "Docker" on hover; testimonials show 6 (desktop) / 2 (mobile) and 10 after "Ver más", and the button hides; accordion allows several items open at once; the theme toggle switches to light, persists in localStorage and survives a reload (`aria-pressed=true`); the navbar background goes from transparent at the top to `bg/60` + blur when scrolled; the mobile menu opens (`aria-expanded=true`) and closes on Escape. **No console errors.**
- Animation probe (`.compare/animprobe.mjs`): hero opacity is 0.6 at about 100ms and 1 once settled; the glow goes 0 → 1; a pricing heading below the fold is at opacity 1 (forwards fill), 0.94 when it has partly entered, and 1 once it's in view.

## Lessons for a migration skill
- **General.** Read the **computed** custom properties on the live demo (`getComputedStyle(documentElement).getPropertyValue('--background')`) before translating tokens. Layered vs. unlayered blocks in shadcn v4 `globals.css` can make the "obvious" palette dead code.
- **General.** Around bejamas interactive components, never rely on `space-x-*`/`space-y-*`/`:last-child`. Use `gap-*`, or give the component root `class="contents"` when it is the only child of a spaced stack. The component's inline `<script>` is a real DOM sibling.
- **General.** Prefer `<Button data-slot="<primitive>-trigger">` over `XTrigger asChild` when the source used `asChild` on a Button. It gives one interactive element instead of a div wrapping a button.
- **General.** shadcn new-york → bejamas Button needs `rounded-md`, `h-8` (sm), `px-4` (default) and `hover:bg-accent dark:hover:bg-accent/50` (ghost). Define a reusable class constant per site.
- **General.** bejamas Card: add `ring-0 border-solid overflow-visible shadow-sm text-base` when matching shadcn cards, especially with custom borders or overflowing badges.
- **General.** Radix `DropdownMenuContent` defaults to `align="center"`, bejamas to `start`. Always pass `align` explicitly.
- **General.** Scroll-driven CSS in Tailwind v4: use longhand animation properties (Lightning CSS shorthand merge bug) and `animation-fill-mode: forwards` for entrance reveals.
- **General.** A responsive "show N then show all" list can be pure CSS + Collapsible: put the always-visible items first, add breakpoint-hidden items with `max-md:group-data-[state=closed]/collapsible:hidden`, and wrap the rest in `CollapsibleContent class="contents"` so they stay in the same grid or column flow.
- **General.** next-themes → `<html class="dark">` + inline head script reading `localStorage.theme`, and a bejamas `Toggle` whose `toggle:change` is mirrored to the class. That stays inside the "derived display" rule.
- **General.** To reproduce a component's box height (e.g. NumberFlow), measure the live element and mimic it with padding in `em`, so the rest of the page keeps identical offsets.
- **Site-specific.** Radix icons (not lucide) are used throughout gonzalochale templates. Render them once from the npm package to static SVG strings.
