# ixartz-saas-boilerplate migration findings

## Summary
- Source: https://github.com/ixartz/SaaS-Boilerplate @ `e3952a7ed5b0ef172ac4363c4644b8c334d1094b` (2026-08-21), Next.js `^16.2.9` (App Router, RSC), React 19, Tailwind v4 (`@tailwindcss/postcss ^4.3.1`, CSS-first config in `src/styles/global.css`), shadcn `new-york` / baseColor `neutral`. UI libs on the landing page: Radix (`react-accordion`, `react-dropdown-menu`, `react-slot`), `@radix-ui/react-icons`, `lucide-react` (accordion chevron), `next-intl` 4, `next/image`. No framer-motion, magic ui, aceternity or embla. Clerk/Drizzle/Sentry exist in the repo but are not used by the home route.
- Demo: https://react-saas.com/
- Port: /tmp/bui-ports/ixartz-saas-boilerplate (preview port 4402)
- Fidelity verdict: **faithful**. Full-page screenshots at 1440, 1024 and 768 px are pixel-identical to the live demo except the rows covered by the required "View original" button. At 390 px the only other differences are sub-pixel anti-aliasing in the banner and resampling of the raster sponsor logos (next/image re-encodes them). Mobile menu, locale dropdown and FAQ accordion behave the same as the original; the open states were compared side by side.
- Effort hotspots: (1) the mobile menu: no primitive can show one panel on mobile and keep it visible on desktop, so the desktop nav is a second static copy; (2) bejamas Button, Badge, Accordion and DropdownMenu defaults that differ from shadcn new-york (radius, padding, shadow, active scale, borders, alignment, radio indicator) and had to be overridden per instance; (3) next-intl messages and rich text, rendered statically.

## Component mapping (shadcn/React → bejamas/Astro)
| Source | Port | Notes on API differences (props, asChild, variants, sizes, default classes) |
|---|---|---|
| `<a className={buttonVariants({variant,size})}>` / `<Link className={buttonVariants()}>` | `<Button as="a" variant size>` | No `asChild`; use `as="a"`. bejamas base is `rounded-lg` (= `--radius`, 10px) while shadcn uses `rounded-md` (8px); bejamas adds `active:scale-98`; `default` adds `shadow-xs`. Sizes differ: default `px-3` vs `px-4`; `lg` `px-5` vs `px-6`; `sm` `h-8.5` vs `h-8`. `outline` has no `bg-background` and hovers to `border-accent`. `ghost` hovers to `bg-secondary`, not `bg-accent` (same colour in this theme). The port adds `rounded-md active:scale-100` plus the shadcn padding/height to every instance |
| `<Button variant="ghost" onClick={toggleMenu}>` (MenuToggle) | `<Button variant="ghost" data-slot="collapsible-trigger">` inside `<Collapsible>` | Passing `data-slot` through Button's rest props makes it the primitive's trigger. DropdownMenuTrigger does the same internally |
| `badgeVariants()` on `<a>` | `<Badge as="a" size="sm" class="h-auto rounded-md px-2 py-0.5">` | Badge's cva `size: default` (`text-sm h-6`) is applied after the base `h-5 text-xs`, so the default badge is larger than shadcn's. `size="sm"` restores `text-xs`. The base forces `rounded-full`, overridden through `class`. Props has no anchor attributes (see Bugs) |
| Radix `Accordion type="multiple"` | `<Accordion multiple>` | `AccordionItem value` is required (same). The trigger defaults to `text-sm py-4 hover:underline border border-transparent`. The transparent border adds 2px per row and a 1px inset, so the port passes `border-0 py-5 text-lg hover:no-underline` |
| shadcn `ChevronRightIcon` with `[&[data-state=open]>svg]:rotate-90` | `<ChevronRight slot="icon" class="… group-aria-expanded/accordion-trigger:rotate-90">` | bejamas swaps between chevron-down and chevron-up icons by default. To get the source's rotating chevron, pass a custom icon in the `icon` slot and use the trigger's `group/accordion-trigger` |
| `AccordionContent` (`text-muted-foreground`, `pt-0 pb-4`) | `<AccordionContent class="text-base text-muted-foreground">` | The bejamas outer wrapper hard-codes `text-sm`, and `class` goes to the inner div. That works here because the inner div sets its own size |
| Radix `DropdownMenu` + `RadioGroup value onValueChange` | `<DropdownMenu defaultValue="en">` + `DropdownMenuRadioItem value` | The root-level `defaultValue` selects the radio. Content defaults: `align="start"` (Radix: `center`), `w-[var(--anchor-width)]` (as wide as a 36px icon trigger, clamped to `min-w-32`), `ring-1 ring-foreground/10` instead of `border`. The port passes `align="center" class="w-auto rounded-md border ring-0"` |
| `DropdownMenuRadioItem` (dot `ItemIndicator` on the left, `pl-8`) | the same, plus utility overrides on the built-in indicator | bejamas renders a check on the right with `pr-8`. It was restyled with literal classes `*:data-[slot=dropdown-menu-radio-item-indicator]:left-2 … :before:size-2 :before:rounded-full :before:bg-current` and `[&_[data-slot=dropdown-menu-radio-item-indicator]_svg]:hidden` |
| `@radix-ui/react-icons` (`TwitterLogoIcon`, `GitHubLogoIcon`, `ArrowRightIcon`) | `src/components/icons/RadixIcon.astro` with the path data copied from the live DOM | Not lucide glyphs, so they are not substituted with `@lucide/astro` |
| `lucide-react` `ChevronRightIcon` | `@lucide/astro` `ChevronRight` | 1:1 |

## Gaps in bejamas/ui (missing components, variants, props, primitives)
- **A disclosure that is collapsible only below a breakpoint (needed by the Navbar).** Upstream toggles `max-lg:hidden` on two sibling panels, so they are always visible at `lg`. `@data-slot/collapsible` controls a single `collapsible-content` and closes it with the `hidden` attribute. Tailwind v4 preflight has `[hidden]:where(:not([hidden="until-found"])){display:none!important}` in the base layer, and an `!important` declaration in an earlier layer beats `!important` in the utilities layer, so `lg:flex!` on the content cannot reveal it on desktop. This was concluded from the cascade rules and was not tested at runtime. Workaround: the Collapsible root gets `class="contents lg:hidden"`, so the trigger and content become flex items of the header row, and the desktop nav and right menu are a second static copy with `max-lg:hidden`. Cost: the links and the LocaleSwitcher appear twice in the DOM (one copy is always `display:none`).
- **HamburgerMenu does not fit this kind of navbar.** It has its own fixed 48px bar (`h-12 … border-b`), a `brand` slot and an absolutely positioned full-viewport panel (`h-[calc(100dvh-3rem)]`), while the source expands an inline rounded `bg-secondary` card below the logo row. Collapsible matched the source exactly.
- **Radio-item indicator placement and shape.** No prop chooses a left dot (Radix/shadcn) or a right check (bejamas). The port changed it with long arbitrary-variant class strings. An `indicator="dot" | "check"` / `indicatorPosition` prop would make this a one-word change.
- **Locale switching.** Only the English page is ported, so selecting "Français" changes the radio state but does not navigate. A script that navigated would go beyond derived display, so the port has none.

## Bugs / issues in bejamas 0.5.0 or its CLI
- **Badge `Props` omits HTML attributes.** `interface Props { as?, variant?, class?, shape?, size? }` does not extend `HTMLAttributes`. `<Badge as="a" href="…">` therefore fails `astro check` with `ts(2322) Property 'href' does not exist on type 'IntrinsicAttributes & Props'`, although the attributes are forwarded at runtime through `...props`. Workaround in `Hero.astro`: `{...twitterLink}` spread. Expected: Props equivalent to the `ButtonAsAnchor` union in Button.
- **Badge default size overrides its own base.** The base class string has `h-5 … text-xs`, but `badgeVariants` `size.default` (`text-sm h-6`) is merged after it, so a default Badge is `h-6 text-sm`. The size utilities in the base string never apply. This may be intended, but it differs from shadcn.
- **DropdownMenu scroll lock shifts centred content.** When the menu opens, `@data-slot/core` `lockScroll()` sets `overflow:hidden; scrollbar-gutter:stable` on `<html>`. In headless Chromium at 1440px (`innerWidth === clientWidth === 1440` both before and after), the centred `max-w-5xl` header moved 7.5px left while the menu was open: the "Sign up" link went from x=1150.3 to x=1142.8, whereas Radix (`react-remove-scroll`) did not shift. This was observed only in the Playwright headless environment and may not reproduce with real overlay scrollbars. Not worked around (lockScroll kept to match Radix's modal default).
- **Scaffold leftovers** (not bugs, but every port has to undo them): the template sets `--primary: oklch(0.4634 0.2647 264.76)` (blue), `--secondary` with hue 286, dark `--accent: oklch(0.371 0 0)`, sidebar tokens, Inter via `BEJAMAS_ASTRO_FONTS`, `/favicon.svg` and `/bejamas.svg`. `astro check` needs `bun add -d @astrojs/check`, which the template does not include.
- `bunx bejamas add accordion badge button collapsible dropdown-menu separator -y` worked; existing identical files were skipped with a clear message. `@data-slot/*` packages were added to `dependencies` automatically.

## Theming, fonts, assets
- **Tokens:** `:root` and `.dark` were copied 1:1 from upstream `src/styles/global.css` (shadcn neutral oklch values). The bejamas-only sidebar tokens were removed. Upstream's `@theme inline` matches the port's apart from bejamas extras (`--font-heading`, `--color-destructive-foreground`). `body` gained `antialiased` as upstream has it. Upstream's compiled CSS reports colours as `lab(…)` and the port's as `oklch(…)`; the screenshots are pixel-identical, so this is only a difference in how colours are serialised.
- **Fonts:** upstream loads no web font (no `next/font`). Computed `font-family` on the live demo is Tailwind's default `ui-sans-serif, system-ui, sans-serif, …`. The port sets `BEJAMAS_ASTRO_FONTS = []` (the fonts API accepts an empty array), removes the `<Font>` tag and defines `--font-sans` (Tailwind's default stack) and `--font-heading: var(--font-sans)` in `:root`. Without that, the bejamas `@theme inline { --font-sans: var(--font-sans) }` refers to itself and the scaffold relies on the Inter font variable.
- **Assets:** favicons (`favicon.ico`, `favicon-16x16.png`, `favicon-32x32.png`, `apple-touch-icon.png`) and 11 sponsor logos were copied from upstream `public/`. Only the files the home page uses were copied.
- **Colour mode:** upstream has no theme provider and nothing adds `.dark`. The live demo renders identically with `prefers-color-scheme: dark` (diff of `original.png` against `original-dark.png`: 0 rows). The port also loads light and ignores the media query, verified the same way.
- **Tailwind v4 → v4:** no config translation was needed. Classes such as `bg-linear-to-r`, `@container` and `@xl:` copy over unchanged.

## Animation & third-party libraries
- No framer-motion or other animation library is used. The only motion is the Radix accordion height animation (`animate-accordion-down/up`), which bejamas' AccordionContent reproduces through `bejamas/tailwind.css` keyframes and `--accordion-panel-height`. The chevron rotation uses `transition-transform duration-200`, as upstream.
- Radix dropdown open/close animations map to bejamas' `data-open:animate-in … zoom-in-95` (tw-animate-css), which look the same.

## Next.js-specific translations
- **Route groups:** the brief points to `src/app/[locale]/(unauth)/`, but at `e3952a7` the home page is `src/app/[locale]/(marketing)/page.tsx`; `(unauth)` no longer exists. This is drift between the brief and the repo, not between the repo and the demo: the live demo matches the source markup exactly.
- **next-intl:** `src/i18n/en.json` is a verbatim copy of `src/locales/en.json`. `src/i18n/index.ts` exposes a build-time `useTranslations(namespace)` that does `{var}` interpolation (`plan_price`, `PricingFeatures`, `footer_text`) and `splitRich()` for the single-tag rich messages (`Hero.title` `<important>`, `Footer.footer_text` `<author></author>`). Locale-prefixed routing (`localePrefix: 'as-needed'`), `setRequestLocale` and `NextIntlClientProvider` were dropped because only the default `en` locale is rendered. `generateMetadata` became the `<title>`/`<meta description>` props on the Layout.
- **next/link (`@/libs/I18nNavigation` Link):** became plain `<a>`. Out-of-scope routes (`/sign-up`, `/sign-in`) point to `https://react-saas.com/sign-up|sign-in`. The footer social icons keep upstream's `href="/"`.
- **next/image:** became `<img width="130" height="…" loading="lazy" decoding="async">`, with heights read from the live DOM (Clerk 38, Sentry 39, Crowdin 27, Arcjet 58, CodeRabbit 21/20, Next.js Boilerplate 30). next/image serves re-encoded `w=256/384 q=75` PNGs, and that accounts for the remaining few-pixel diffs in the logo row at 390px.
- **Client components:** `CenteredMenu` (`'use client'` + `useMenu` state) became Collapsible. `LocaleSwitcher` (`'use client'`, `useRouter`) became a static DropdownMenu. Everything else was a server component and is now plain Astro.
- **Layout-level components:** `DemoBadge` lives in `app/[locale]/layout.tsx`, so it went into `Layout.astro` next to the comparison button.
- `new Date().getFullYear()` in the footer runs at build time instead of on each request.

- `bun run build`: 1 page and 3 client scripts (accordion, collapsible, dropdown-menu), no warnings. `bunx astro check`: 0 errors, 0 warnings (1 hint for the scaffold's unused `fontProviders` import).
- Pixel diff (`.compare/diff.mjs`, which reports rows whose per-pixel RGB difference sum exceeds 60) against `https://react-saas.com/` with identical page heights:
  - 1440px (height 3618 for both): only rows 837–886, the fixed "View original" button.
  - 1024px and 768px: only the button rows.
  - 390px (height 6581 for both): button rows 792–830, banner text rows 23–35 (sub-pixel anti-aliasing, visually identical in `crop-banner.png`), and logo rows 1106–1262 (next/image resampling).
  - `--dark`: identical to light, as on the original.
- Interactive checks (`.compare/interact.mjs`, run against both sites with identical results): the mobile menu opens and closes (the "Pricing" link toggles between 1 and 0 visible); the mobile LocaleSwitcher inside the open menu shows 2 radio items; the desktop LocaleSwitcher shows `English`/`Français` with English checked; the FAQ opens multiple items (`aria-expanded` `true,true,false,…`) and closes on re-click; no console errors. Side-by-side crops: `crop-menu.png`, `crop-locale.png`, `crop-faq.png`. The two LocaleSwitcher instances (mobile and desktop) work independently.
- Remaining differences: the 7.5px header shift while the dropdown is open (scroll lock, headless only); the Radix dropdown makes the body `pointer-events:none` (modal) and bejamas does not, so the trigger keeps its hover background while open; "View original" overlaps the right part of the Demo badge.

## Lessons for a migration skill
- (general) **Measure before styling.** A probe that dumps computed font, size, colour and rect for every text leaf on both sites, plus a canvas-based row diff of full-page screenshots, finds 1–2px offsets that eyeballing misses. The accordion's transparent 2px border was found this way.
- (general) **The bejamas Button is not shadcn new-york's Button.** For a faithful shadcn port, add `rounded-md active:scale-100` everywhere, `shadow-none` on `default`, and shadcn padding (`px-4`, `lg: px-6`, `sm: h-8`). Consider a shared constant per size, or a "shadcn-compat" theme for ports.
- (general) **Breakpoint-only disclosures (mobile nav that is always open on desktop)** cannot reuse one Collapsible content node because of the `hidden` attribute and preflight `!important`. Use `class="contents lg:hidden"` on the Collapsible root so the trigger and panel stay in the header's flex row, and render a static desktop copy.
- (general) To turn any bejamas `Button` into a primitive trigger, pass `data-slot="<primitive>-trigger"`. Button forwards it, so no `asChild` is needed.
- (general) Tailwind only sees literal class strings. Classes built with template literals (`${prefix}:left-2`) are silently dropped. Keep override strings literal even when they are long.
- (general) Restyling a component's built-in internal part (e.g. a dropdown indicator) works with `*:data-[slot=…]:` and `[&_[data-slot=…]_svg]:hidden` without editing `src/ui`.
- (general) Sites with no `next/font` use Tailwind's system stack: empty `BEJAMAS_ASTRO_FONTS` and define `--font-sans` explicitly, otherwise the scaffold's Inter and self-referencing `@theme` variable leak in.
- (general) Read `next/image` intrinsic `width`/`height` from the live DOM instead of computing them. Expect small raster diffs from Next's re-encoding.
- (general) For next-intl sites, copy the messages JSON verbatim and use a tiny build-time `t()` with `{var}` interpolation and single-tag rich splitting. This keeps copy changes traceable to the source file.
- (general) Copy long SVG path data programmatically from the source or the live DOM. Retyping it invites silent changes.
- (specific) ixartz's `Section` (`@container px-3 py-16` + `mx-auto max-w-5xl`) is reused by every section, so one Astro `Section.astro` with `title/subtitle/description` props covers the whole page.
- (specific) The brief's `(unauth)` path is stale; the landing page is in `(marketing)`.
