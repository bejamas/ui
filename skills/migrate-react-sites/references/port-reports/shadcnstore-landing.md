# shadcnstore-landing migration findings

## Summary
- Source: https://github.com/shadcnstore/shadcn-dashboard-landing-template @ `65fc11224e96d56a62e224a58f7ed590aea5ac24`, `nextjs-version/` (Next.js 16.1.1, React 19.2.3), Tailwind v4.1.18 (`@tailwindcss/postcss`, `tw-animate-css`), shadcn `new-york` / base color `neutral`, CSS variables. UI libs: Radix (navigation-menu, dialog/Sheet, collapsible, accordion, toggle-group, avatar, separator), lucide-react 0.562, react-hook-form + zod (contact and newsletter forms), a custom `ThemeProvider` (not next-themes) with `defaultTheme="system"`, and a custom landing theme customizer. No framer-motion, Magic UI or embla on the landing page.
- Demo: https://shadcnstore.com/templates/dashboard/shadcn-dashboard-landing-template/landing. The demo is the repo's `vite-version/` build, not the Next.js build (see Verification).
- Port: /tmp/bui-ports/shadcnstore-landing (preview port 4406). Astro 7.3.5, bejamas 0.5.0, Tailwind 4.3.3, @data-slot/* 1.1.1, @lucide/astro 1.52.0.
- Fidelity verdict: **faithful** for layout, copy, assets, colors and typography. Section offsets and heights are identical to the demo at 390, 768, 1280 and 1440 px, and pixel diffs are 0–0.7% per viewport chunk (the remaining differences are the marquee phase, the customizer trigger and the comparison button). Documented approximations: the theme customizer is out of scope, the theme toggle has no circular view-transition, and the forms use native validation instead of zod messages.
- Effort hotspots: (1) bejamas default classes that drift from shadcn new-york: Card border, Badge size, Button radius and padding, CardTitle, FieldLabel line-height, link variant color. (2) Mega menu placement (data-slot aligns to the trigger, Radix aligns to the root) and Sheet → Drawer. (3) Setup gaps: lucide brand icons are missing and `marquee` ships without its keyframes.

## Component mapping (shadcn/React → bejamas/Astro)
| Source | Port | Notes on API differences (props, asChild, variants, sizes, default classes) |
|---|---|---|
| `Button` (`asChild` + `<Link>`/`<a>`) | `Button as="a" href=…` | bejamas defaults to `rounded-lg`, `px-3` at default size (shadcn `px-4`), `px-5` at `lg` (shadcn `px-6`), outline has no `bg-background`, ghost hovers `bg-secondary`, and `active:scale-98`. Parity classes in `src/lib/site.ts` (`btn`, `btnDefault`, `btnLg`, `btnOutline`). `variant="link"` uses `text-accent`, which is near-white in the neutral theme, so pass `text-primary`. |
| `<Button><a>…<Icon/></a></Button>` (features section, invalid nesting) | `Button as="a"` with the icon as a direct child | The source's icon is not a direct child, so `has-[>svg]:px-4` never applied there. The port forces `has-[>svg]:px-6` to keep the 195px width. Conversely, in the CTA the source's `px-8` loses to `has-[>svg]:px-4`. Always reproduce the cascade, not the class string. |
| `Badge variant="outline"` | `Badge variant="outline" class="h-auto rounded-md px-2 py-0.5 text-xs"` | bejamas Badge is `rounded-full`, `h-6`, `text-sm` by default (size variant), while shadcn is `rounded-md`, auto height and `text-xs`. |
| `Card` / `CardContent` / `CardHeader` / `CardTitle` | same names | bejamas Card = `ring-1 ring-foreground/10` + `border-none … border border-border` + `shadow-lg` + `text-sm` + `overflow-clip`. The net border-style is **none** (see Bugs), so the visible edge is the ring. For parity: `ring-0 border-solid shadow-sm text-base`. `CardTitle` is `text-lg md:text-xl font-medium font-heading`; shadcn is `leading-none font-semibold` at the inherited size. |
| `NavigationMenu*` (Radix) | `NavigationMenu*` (@data-slot/navigation-menu) | Trigger defaults to `text-base` (shadcn `text-sm`). List has `gap-0` (shadcn `gap-1`). The viewport aligns to the **trigger**, while Radix's sits under the menu root: fixed with `alignOffset`. Content needs `value` on the item. The trigger hover/open backgrounds use `data-open`/`data-popup-open` variants instead of `data-[state=open]`. |
| `NavigationMenuLink` with `onClick` smooth scroll | `NavigationMenuLink href="#…"` + `html { scroll-behavior: smooth }` | The source already sets `scroll-behavior: smooth` globally, so the JS `scrollIntoView` is redundant. |
| `Sheet side="right"` (Radix Dialog) | `Drawer side="right"` | The Drawer popup width is a global `width: 340px` rule, so it needs `w-full! sm:w-[400px]!` and `rounded-none!`. It also has `border` on all sides plus `p-4 gap-4` (→ `border-y-0 border-r-0 p-0 gap-0`). The built-in close is `DrawerClose`, and `[&>button]:hidden` is not needed. |
| `Collapsible` controlled (`open`/`onOpenChange`) + chevron rotate on state | `Collapsible` / `CollapsibleTrigger` / `CollapsibleContent` | Chevron rotation via `group-aria-expanded/…:rotate-180` on the trigger instead of React state. |
| `Accordion type="single" collapsible` | `Accordion` (single + collapsible are defaults) | Trigger `data-[state=open]:border-b` → `aria-expanded:border-b`. Default icon swaps two SVGs (down/up), so the rotating chevron goes through `<ChevronDown slot="icon" …>`. The `class` on AccordionContent lands on the inner div (same as shadcn). |
| `ToggleGroup type="single" value/onValueChange` | `ToggleGroup defaultValue="monthly"` + `toggle-group:change` listener | The item padding override must be `group-data-[spacing=0]/toggle-group:px-6`, because the item ships `group-data-[spacing=0]/toggle-group:px-2`, which beats a plain `px-6`. |
| `Avatar`/`AvatarImage`/`AvatarFallback` | same | `AvatarImage` with a missing `src` renders a div slot. For known-404 images the port omits `AvatarImage` (the broken-image gap from the earlier findings still applies to live URLs). |
| `Separator orientation="vertical"` | `Separator orientation="vertical"` | Same API. `!h-4` still needed. |
| `Form`/`FormField`/`FormItem`/`FormLabel`/`FormMessage` + `Input`/`Textarea` | `Field` / `FieldLabel` / `Input` / `Textarea` | `FieldLabel` is `leading-snug`, while shadcn `FormLabel` is `leading-none`. Each field grew 5px (the contact section was 21px taller) until `class="leading-none"` was added. Input is `rounded-lg` with `data-[size=default]:px-3`. Override with `rounded-md`. |

## Gaps in bejamas/ui (missing components, variants, props, primitives)
- **Theme customizer** (`landing-theme-customizer.tsx`: Sheet with theme presets, tweakcn import, radius, color pickers, plus a floating gear trigger fixed at `right-4 top-1/2`): out of scope per the assignment. It needs a color-picker primitive (already a known gap) and runtime CSS-variable editing. Neither the panel nor its trigger is rendered. The pixel diff at the gear position (rows ~400–450 of chunk 1) is this omission.
- **Theme (dark-mode) toggle**: bejamas has no theme-mode primitive or provider, and the Astro scaffold has no dark-mode bootstrap at all. The port uses an inline `<head>` script equivalent to the source `ThemeProvider` (system default, `localStorage` key `vite-ui-theme`, the demo's key) and the bejamas `Toggle` (`@data-slot/toggle`) as the control. A small script mirrors `toggle:change` onto `<html class>` and keeps both toggles (header + drawer) in sync with `toggle:set`. The source's circular reveal (`useCircularTransition`, View Transitions API) is dropped.
- **NavigationMenu viewport anchoring**: @data-slot/navigation-menu positions the viewport relative to the active trigger (`start`/`center`/`end`) and has no "align to menu root" mode, while Radix renders the viewport under the root. Workaround: `alignOffset={-170}` (constant distance from the list start to the Solutions trigger at `xl`). This breaks if nav labels change.
- **Drawer has no close-on-link-select option**: `HamburgerMenu` closes on `a[href]` clicks internally, but `Drawer` does not. The Sheet in the source called `setIsOpen(false)` on every link. The port dispatches the inbound `drawer:close` event from link clicks. References are captured at init, because the portal reparents the popup to `<body>`.
- **ToggleGroup single mode can become empty**: pressing the active item deselects it (both pills "off"). The source is a controlled Radix group where `onValueChange("")` leaves `isYearly` unchanged, so one item always stays on. @data-slot/toggle-group has no `required`/non-empty option. The port re-asserts the last value with `toggle-group:set` when `toggle-group:change` reports `[]`. This is the same idea as emulating a controlled prop with set events. Candidate primitive option: `data-required` / `allowEmpty: false`.
- **HamburgerMenu vs Sheet**: `HamburgerMenu` renders its own `h-12` bar plus a top dropdown panel, so it can't reproduce a right-side Sheet with the original `h-16` header. `Drawer` is the right mapping for shadcn `Sheet`.
- **Forms**: no bejamas equivalent of shadcn `Form` (react-hook-form + zod field messages). The port uses native constraint validation. The source `onSubmit` only `console.log`s and resets, so a tiny script does `preventDefault()` + `reset()`. Without it, a GET submission would serialize the form, including email, into the page URL.

## Bugs / issues in bejamas 0.5.0 or its CLI
- **`bejamas add marquee` ships no keyframes.** `Marquee.astro` uses `[animation:marquee-x_var(--duration)_linear_infinite]`, but neither `bejamas/tailwind.css` nor the registry item (`apps/web/public/r/marquee.json` has no `css`/`cssVars`) defines `@keyframes marquee-x`/`marquee-y`. They exist only in the docs app's `packages/ui/src/styles/globals.css`. Observed: a static marquee. Expected: scrolling. Fix in the port: copy the keyframes into `src/styles/globals.css`.
- **Card border is cancelled out.** The installed `Card.astro` class string contains `border-none` and later `border border-border`. tailwind-merge keeps both (border-style vs border-width groups). `border-none` sets `--tw-border-style: none` and `border` uses `border-style: var(--tw-border-style)`, so the computed border is none and only `ring-1 ring-foreground/10` draws the edge. Overriding `ring-0` (to match shadcn) makes cards borderless until you add `border-solid`. This also changed text wrapping inside testimonial cards (1px narrower content box with `text-balance`).
- **`Button variant="link"` uses `text-accent`.** In the neutral theme `--accent` is `oklch(0.97 0 0)` (light) and `oklch(0.269 0 0)` (dark), so link buttons are near-invisible against the background. shadcn uses `text-primary`.
- **Scaffold Layout has no color-mode handling.** `src/layouts/Layout.astro` from `bejamas init -t astro` ships `.dark` tokens in `globals.css` but no script or class strategy, so `prefers-color-scheme: dark` users always get light.
- **Scaffold default theme leaks a blue primary**: `--primary: oklch(0.4634 0.2647 264.76)` in both `:root` and `.dark` even with `-b neutral`. It must be replaced wholesale with the source tokens.
- **Drawer scroll lock in headless Chromium**: when open, the drawer sets `html { overflow: hidden; scrollbar-gutter: stable }`. With Playwright (`--hide-scrollbars`) this reserves a 15px gutter, so the full-width drawer measures 375px in a 390px viewport. Radix (react-remove-scroll) measures the real scrollbar width (0) instead. On macOS overlay scrollbars this is likely invisible. Recorded as observed in headless only.
- CLI note: `bunx bejamas add … -y` printed "Skipped N files (files might be identical…)" for shared deps (`utils.ts`, `label`, `separator`). Harmless.

## Theming, fonts, assets
- Tokens: `:root` and `.dark` copied 1:1 from `nextjs-version/src/app/globals.css` (oklch neutral, `--radius: 0.625rem`), replacing the scaffold's blue primary. The `@theme inline` mapping in the scaffold already matches shadcn v4, plus `--font-heading`. `--font-heading` is set to `var(--font-sans)`, because the source has no heading font.
- Tailwind v4 → v4: every source utility worked unchanged, including `perspective-distant`, `transform-3d`, `rotate-x-8`, `translate-z-16`, `bg-linear-to-l`, `bg-radial`, `z-15`, `grid-rows-subgrid` and `min-h-50`. TW v4 `container` is width-only (max-width per breakpoint, no centering or padding). The source always pairs it with `mx-auto px-4 sm:px-6 lg:px-8`, so it was copied verbatim and the geometry matched exactly (logo at x=112 at 1440px).
- Fonts: `next/font/google` Inter (`--font-inter`, mapped to `--font-sans`) → Astro fonts API `fontProviders.google()` Inter with `weights: ["100 900"]`, `styles: ["normal"]`, `fallbacks: ["system-ui","sans-serif"]` on `--font-sans`, and `<Font cssVariable="--font-sans" preload />`. Computed h1 on both: Inter 72px/72px, weight 700, letter-spacing -1.8px.
- Assets: `dashboard-{light,dark}.png`, `feature-{1,2}-{light,dark}.png`, `favicon.png`, `favicon-dark.png` and `favicon.ico` copied from the source `public/`. External images were vendored: 6 Unsplash portraits (`public/team/*.jpg`; ids `1494790108755-…` and `1566492031773-…` return 404 upstream, so they render fallbacks as on the demo), 12 notion-avatars SVGs (`public/avatars/`) and `ui.shadcn.com/placeholder.svg`. The favicon pair with `media="(prefers-color-scheme: dark)"` follows the demo's `<head>`.
- Brand SVGs: the 12 Simple Icons paths in the logo carousel and the ShadcnStore `Logo` are inlined in Astro components.

## Animation & third-party libraries
- No framer-motion or Magic UI on the landing page. All motion is CSS in the source and was kept as is: Image3D hover tilt/shimmer, button `hover:scale-105`, `group-hover:translate-x-1` arrows, accordion height animation (bejamas `animate-accordion-down/up`) and the nav-menu viewport transitions (data-slot).
- Logo scroll: the hand-rolled `@keyframes logo-scroll` (−144rem / 30s) is replaced by bejamas `Marquee` (duplicated track, `translateX(-100%)`) with the duration tuned to the same speed. The source loop actually jumps, because 144rem ≠ the 2496px track. Marquee loops seamlessly, a minor improvement.
- Theme toggle circular reveal (`use-circular-transition` + `circular-transition.css`): dropped.

## Next.js-specific translations
- `next/image` (`priority`, `width/height`) → plain `<img>` with the same intrinsic `width/height` attributes, `fetchpriority="high"` on the hero light image and `loading="lazy"` elsewhere. No Astro `<Image>`: the PNGs are served as-is, as on the Vite demo.
- `next/link` → `<a>`/`Button as="a"`. `/dashboard`, `/auth/sign-in` and `/auth/sign-up` point to the matching demo URLs (`https://shadcnstore.com/templates/dashboard/shadcn-dashboard-landing-template/{dashboard,auth/sign-in,auth/sign-up}`), the targets the live demo uses.
- `next/font/google` → Astro fonts API (above).
- `metadata` export (title, description, keywords, OpenGraph, Twitter) → `<head>` tags in `Layout.astro`.
- `"use client"` everywhere, but most sections have no hooks. Only the navbar (`useState`, `useTheme`), pricing (`useState`), contact/footer (`useForm`) and the customizer hold state.
- Custom `ThemeProvider` (not next-themes; `defaultTheme="system"`) → inline head script. It runs before paint, so there is no flash of the wrong theme.

## Lessons for a migration skill
- **(General)** Before porting sections, write parity class constants for Button/Badge/Card/CardTitle/FieldLabel/Input. bejamas defaults are not shadcn new-york defaults: radius `rounded-lg` vs `rounded-md`, Button padding, Badge `rounded-full h-6 text-sm`, Card ring vs border, `text-sm` on Card, CardTitle size, FieldLabel `leading-snug`. Measuring section heights against the original caught every one of these within two iterations.
- **(General)** Compare section `top`/`height` on both pages at several widths with a small Playwright script. It finds 1–5px drift (a label line-height, a border) that screenshots hide, and it's cheaper than reviewing 60 chunks.
- **(General)** Reproduce the source's *effective* cascade, not its class strings. `has-[>svg]:px-4` silently overrides `px-8` in shadcn's Button when the icon is a direct child, and does not apply when the source nests `<a>` inside `<Button>`.
- **(General)** In bejamas components, variant-prefixed defaults (`group-data-[spacing=0]/toggle-group:px-2`, `data-[size=default]:px-3`) beat plain utility overrides. Override with the same prefix.
- **(General)** `ring-0` on a bejamas Card removes its only visible edge. Add `border-solid` to get shadcn's 1px border.
- **(General)** Add the marquee keyframes yourself after `bejamas add marquee`. Import brand icons (Github, Twitter, Linkedin, Youtube…) as inline SVGs: @lucide/astro fails the build with `MISSING_EXPORT`.
- **(General)** Add a color-mode bootstrap script to the scaffold Layout and replace the scaffold's blue `--primary` in both `:root` and `.dark`.
- **(General)** shadcn `Sheet` → bejamas `Drawer` (not HamburgerMenu). Override the global 340px width with `w-full!`/`sm:w-[…]!` and `rounded-none!`, and close on link clicks via the `drawer:close` event.
- **(General)** For a Radix NavigationMenu mega menu, the data-slot viewport anchors to the trigger. Use `alignOffset` to reproduce root anchoring and verify the box against the live demo.
- **(General)** For controlled single-select Radix ToggleGroups (pricing toggles), re-assert the last value via `toggle-group:set` when the change event reports an empty selection.
- **(General)** Don't let demo forms submit natively: without an action, the GET submission puts emails in the URL. Mirror the source's no-backend behavior (`preventDefault` + `reset`).
- **(Site-specific)** ShadcnStore's live demo is the Vite build of the same repo. Diff `vite-version` against `nextjs-version` before treating demo-vs-source differences as drift.
- **(Site-specific)** Two Unsplash portrait URLs in the team data are dead upstream. The demo shows initials, and so should the port.
