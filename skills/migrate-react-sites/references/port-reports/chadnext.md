# chadnext migration findings

## Summary
- Source: https://github.com/moinulmoin/chadnext @ `1a1f25a6de88453bd3c80efa8c3f61f9c159661c`, Next.js 16.0.10 (App Router, `[locale]` segment), React 19.2, Tailwind v3.4.17 (+ `tailwindcss-animate`, `@tailwindcss/typography`), shadcn style `default` / base color `slate` with CSS variables, Radix primitives (accordion, dialog-as-Sheet, dropdown-menu), lucide-react 0.471, next-themes, next-international. No framer-motion, Magic UI, Aceternity or Embla on the home page.
- Demo: https://chadnext.moinulmoin.com/en
- Port: /tmp/bui-ports/chadnext (preview port 4404)
- Fidelity verdict: **faithful**. Full-page heights match exactly at 1440px (3885px) and 390px (5364px), in light and dark. Section, card and accordion y-positions match the live demo to the pixel (measured with Playwright, see Verification).
- Effort hotspots: (1) undoing bejamas-juno defaults on Button/Card/AccordionTrigger to get back to shadcn "default" geometry; (2) Tailwind v3 to v4 behavior differences (container, line-height and responsive font size, gradient stop reset, palette, shadow scale); (3) Drawer geometry, which ships as unlayered global CSS that Tailwind classes cannot override.

## Component mapping (shadcn/React → bejamas/Astro)
| Source | Port | Notes on API differences (props, asChild, variants, sizes, default classes) |
|---|---|---|
| `<Link className={buttonVariants()}>` | `<Button as="a" href>` | No `asChild`/`buttonVariants` export; use `as="a"`. bejamas-juno Button defaults differ: `rounded-lg` vs `rounded-md`, default `h-9 px-3` vs `h-10 px-4 py-2`, lg `h-10 px-5` vs `h-11 px-8`, `shadow-xs`, `active:scale-98`, and **`has-[>svg]:px-2.5`** (default) / `has-[>svg]:px-4` (lg). The last one silently narrows any button with a direct `<svg>` child (the hero "1.3K ★ on GitHub" button), so `has-[>svg]:px-4` has to be added explicitly; tailwind-merge does not drop it when you pass `px-4`. Outline in dark mode is `dark:bg-input/30 dark:border-input`, while shadcn uses `bg-background`. All overrides are in `src/lib/shadcn.ts`. |
| `Card` | `Card` | bejamas Card: `rounded-xl py-6 gap-6 ring-1 ring-foreground/10 shadow-lg text-sm` plus `border-none … border border-border`. Override: `gap-0 py-0 rounded-lg border border-solid ring-0 shadow-xs text-base`. **`border-solid` is required** (see Bugs). `text-base` is needed because shadcn Card text inherits 16px. |
| `CardHeader` (`flex flex-col space-y-1.5 p-6`) | `CardHeader class="flex flex-col gap-0 space-y-1.5 p-6"` | bejamas header is a container-query grid with `px-6`, no vertical padding (the Card owns `py-6`). |
| `CardTitle` (`text-2xl font-semibold leading-none tracking-tight`, Inter) | `CardTitle` + `font-sans text-2xl md:text-2xl font-semibold leading-none tracking-tight` | bejamas title is `font-heading text-lg md:text-xl font-medium text-balance`. You must override the `md:` size too, because tailwind-merge keeps `md:text-xl` when you pass `text-2xl`. `font-heading` would otherwise switch the title to Cal Sans. |
| `CardContent` / `CardFooter` (`p-6 pt-0`) | same parts + `p-6 pt-0` / `justify-center p-6` | bejamas Footer defaults to `justify-between px-6`. |
| `Accordion type="single" collapsible` | `Accordion` (defaults) | Props are `multiple` / `collapsible` / `defaultValue`, not `type`. |
| `AccordionTrigger` (`py-4 font-medium hover:underline`, 16px, rotating ChevronDown) | `AccordionTrigger class="items-center rounded-none border-0 text-base"` + `slot="icon"` ChevronDown with `group-aria-expanded/accordion-trigger:rotate-180` | bejamas trigger defaults to `text-sm items-start rounded-md border border-transparent`, and its built-in icon *swaps* chevron-down/chevron-up in `text-muted-foreground`. To keep the original's rotating foreground chevron, pass an icon through the `icon` slot and color the `<svg>` itself, which beats the `**:data-[slot=accordion-trigger-icon]:text-muted-foreground` rule on the wrapper. |
| `Sheet` / `SheetTrigger` / `SheetContent side="right"` | `Drawer side="right"` / `DrawerTrigger` / `DrawerContent` / `DrawerClose` | Radix Sheet renders its own close X; with Drawer you add `DrawerClose` yourself. The width (`w-3/4 sm:max-w-sm`), square corners and `bg-black/80` overlay need unlayered CSS in `globals.css` (see Gaps/Bugs). The controlled `open`/`setIsModalOpen(false)` on link click is unnecessary because the links navigate away. |
| `DropdownMenu` + `DropdownMenuTrigger asChild><Button variant="ghost" size="sm" className="w-9 px-0">` | `DropdownMenu` + `DropdownMenuTrigger variant="ghost" size="sm" class="h-9 w-9 px-0 …"` | The bejamas trigger *is* a Button and takes Button props directly, so `asChild` is not needed. Ghost hover is `bg-secondary` (same color as `accent` in this theme). |
| `DropdownMenuItem onClick={() => setTheme("dark")}` | `DropdownMenuItem value="dark"` + one listener on `dropdown-menu:select` | `onClick` → `value` + root event `detail.value`. |
| `DropdownMenuContent` (`rounded-md border p-1 shadow-md min-w-[8rem]`) | `DropdownMenuContent class="min-w-[8rem] rounded-md border ring-0 p-1 shadow-md"` | bejamas uses `ring-1 ring-foreground/10 rounded-lg`. |

## Gaps in bejamas/ui (missing components, variants, props, primitives)
- **Dismissible / closable surface**: no primitive for a "dismiss this banner" control. The announcement banner uses Collapsible (default open, trigger inside the content). It works (trigger gets `aria-expanded`, the content gets `hidden`), but semantically it is a disclosure, not a dismiss. An `Alert` with a close part, or a `dismissible` primitive, would fit better.
- **Drawer has no class hook for the backdrop**, and its popup geometry (width 340px, rounded inner corners) lives in `DrawerContent.astro`'s unlayered `<style is:global>`. A shadcn Sheet (`w-3/4 sm:max-w-sm`, square, `bg-black/80` overlay) cannot be expressed through `class`. The port adds `[data-slot="drawer-popup"][data-swipe-direction="right"].sheet-panel { width: 75%; border-radius: 0 }` and `[data-slot="drawer-backdrop"] { background-color: rgb(0 0 0 / .8) }` to `globals.css`. A `size`/`width` prop or a `backdropClass` prop would avoid this.
- **DropdownMenuItem as a link**: there is no `as="a"`/`href` on items, so the locale menu's "French" item navigates through a `dropdown-menu:select` listener (`window.location.href = …/fr`). Same pattern for the theme items (`window.__setTheme(value)`). Both listeners only read the primitive's select event.
- **Theme provider**: no next-themes equivalent ships with the template. The port adds a ~20-line inline head script (localStorage key `theme`, `system` default, `matchMedia` listener) and `window.__setTheme`. A small official `theme` helper or a recipe would help every port.
- **Lucide brand icons**: `@lucide/astro` has no `twitter`/`github` icons (removed upstream). The lucide 0.471 Twitter path is inlined in `Hero.astro`, and the GitHub path is copied from the source's `icons.tsx`.

## Bugs / issues in bejamas 0.5.0 or its CLI
- **Card border never renders.** `Card.astro` merges `"… bg-card border-none … border border-border …"`. tailwind-merge keeps `border-none` (border-style: none) next to `border` (width), so the computed border is `0px`. A consumer `class="border"` does not help either. Repro: `<Card class="border">` → `getComputedStyle(card).borderTopWidth === "0px"`. Workaround: add `border-solid`. Expected: either no border classes or a working border.
- **`bejamas add` adds `shadcn` to devDependencies** (`"shadcn": "^4.21.3"` appeared in `package.json` after `bunx bejamas add card badge accordion …`). This is unexpected in an Astro/bejamas project.
- **Scaffolded `globals.css` sets `:root { --font-heading: var(--font-sans); }`.** When a second `<Font cssVariable="--font-heading">` is added, this rule competes with the variable the Font component emits. The obvious edit, `--font-heading: var(--font-heading)`, is a self-reference that makes the variable invalid. The line has to be deleted when a real heading font is configured. The CLI/template could leave `--font-heading` to the fonts block.
- **DropdownMenu scroll lock reserves a gutter.** Opening a menu sets `html { overflow: hidden; scrollbar-gutter: stable }`. In headless Chromium (hidden scrollbars) this shrinks the layout by 15px and visibly shifts fixed elements (the banner right edge moved from 1440 to 1425). On macOS overlay scrollbars it has no visible effect. Radix's RemoveScroll did not shift the original. Low severity and environment-dependent. The same lock makes the Drawer's `width: 75%` resolve against 375px instead of 390px in headless mobile screenshots (281px vs the original's 292.5px).
- `bunx astro check` prompts interactively to install `@astrojs/check` (not in the template), so it was skipped. `bun run build` passes.

## Theming, fonts, assets
- **Colors**: the original stores bare HSL triplets (`--primary: 222.2 47.4% 11.2%`) and wraps them in `hsl(var(--x))` in `tailwind.config.js`. The port puts `hsl(...)` in the token (`--primary: hsl(222.2 47.4% 11.2%)`) so the template's `@theme inline { --color-primary: var(--primary) }` works unchanged. All `:root` and `.dark` values were copied 1:1, including `--radius: 0.5rem`. Every bejamas oklch default (blue primary, neutral grays, 0.625rem radius) is replaced. Opacity modifiers (`text-primary/70`) become `color-mix(in oklab, …)` in v4, which looks the same.
- **Container**: the v3 config `container: { center: true, padding: '1.5rem', screens: { '2xl': '1400px' } }` gives full width below 1400px and max 1400px above. v4's `container` has per-breakpoint max-widths and no centering/padding. The port defines `@utility site-container { width:100%; margin-inline:auto; padding-inline:1.5rem; max-width:1400px }`. The banner uses `container mx-auto px-4`, where `px-4` beat the container padding in v3, so it is written explicitly as `mx-auto max-w-[1400px] px-4`.
- **Tailwind v3 → v4 line-height**: `font-heading text-3xl leading-[1.1] sm:text-3xl md:text-6xl` renders `md:` with line-height 1 in v3, because the responsive font-size utility resets line-height and wins over the base `leading-*`. In v4 an explicit `leading-*` wins at every breakpoint, so the "Proudly Open Source" heading was 6px taller. Fixed with `sm:leading-9 md:leading-none`. **General rule: wherever a base `leading-*` coexists with responsive `text-*` sizes, add the matching responsive `leading-*`.**
- **Gradient text**: `bg-gradient-to-br from-gray-900 via-gray-800 to-gray-400 dark:from-gray-100 dark:to-gray-900`. In v3, `dark:from-*` rewrites `--tw-gradient-stops` and drops the `via` stop, so dark mode is a two-stop gradient. This is reproduced in a scoped `<style>` with v3 hex grays rather than relying on v4's different stop composition and oklch palette.
- **Palette**: v3 `blue-100/200/700` (pill) and `gray-*` (gradient) were written as v3 hex arbitrary values (`bg-[#dbeafe]`, `text-[#1d4ed8]`), because v4's oklch palette shifts hue and chroma slightly.
- **Shadows**: v3 `shadow-sm` equals v4 `shadow-xs`. Used for Card. `shadow-lg`/`shadow-md` are unchanged.
- **Fonts**: `next/font/google` Inter (`--font-sans`) → `fontProviders.google()` with `weights: ["100 900"]`. `next/font/local` `CalSans-SemiBold.woff2` (`--font-heading`) → `fontProviders.local()` with the file copied to `src/assets/fonts/`. **next/font/local without a `weight` emits a 400 face, so `font-bold` Cal Sans headings (hero h1, "Pricing") get synthesized bold.** The port declares the variant as `weight: 400` to reproduce that heavier look. Declaring it as 600 or a range would make those headings visibly thinner than the demo. Two `<Font>` tags in the layout, both `preload`.
- **Assets**: `chad-next.png`, `favicon.ico`, `favicon-16x16.png`, `apple-touch-icon.png`, `android-chrome-*.png` copied from `public/`. Brand SVGs copied from `shared/brand-icons.tsx` into `BrandIcon.astro`; the path data was extracted programmatically and verified identical. The UploadThing `clipPath id="a"` is made unique per instance.
- **Color mode**: the source is `ThemeProvider attribute="class" defaultTheme="system" enableSystem`. The demo "loads dark" only because the viewer's OS is dark. The port reproduces the system default, so it loads dark in a dark-preference browser and light otherwise, the same as the demo in both `--dark` and light screenshots. The stored choice uses the same localStorage key (`theme`).

## Animation & third-party libraries
- No motion libraries on the home page. `tailwindcss-animate` was used only by Radix Sheet/Dropdown/Accordion enter/exit. The bejamas equivalents (tw-animate-css on DropdownMenuContent, Drawer `transform` transition, accordion height keyframes from `bejamas/tailwind.css`) cover those. Sheet slide-in is now a 250ms transform transition instead of 500ms in / 300ms out keyframes, so it is slightly faster.
- The hero h1 has `duration-300 ease-linear` without any `transition-*` in the source (a no-op). Kept as-is.
- Theme toggle sun/moon rotate/scale swap is plain CSS (`dark:-rotate-90 dark:scale-0`) and ported unchanged.

## Next.js-specific translations
- `next/link` → `<a>`; internal routes (`/login`, `/changelog`, `/about`, `/dashboard/billing`) point at the live demo (`https://chadnext.moinulmoin.com/en/...`). The logo link stays `/`.
- `next/image` (`/chad-next.png`, width/height 30 and 24) → plain `<img>` with the same attributes.
- `next/font/google` + `next/font/local` → Astro fonts API (see Theming).
- `next-themes` → inline head script (see Gaps).
- `next-international` (`getScopedI18n("hero")`, etc.) → English strings copied into `src/config/en.ts`. The locale toggler's French item links to the demo's `/fr`.
- Async server component `Hero` fetching GitHub stars with `revalidate: 3600` → build-time `fetch` in Astro frontmatter with a `1300` fallback (renders "1.3K", same as the demo), through the copied `nFormatter`.
- `getCurrentSession()` / `getUserSubscriptionPlan()` in Header and Pricing → signed-out branch rendered statically.
- `generateMetadata` → static `<title>`, description, OG/Twitter meta, icons and `theme-color` metas in `Layout.astro`. The OG image route (`/api/og`) and manifest are not ported.
- The `@loginDialog` parallel route, Toaster and the umami analytics script are omitted.

## Verification
- `bun run build`: passes with no warnings (1 page, 3 font files copied).
- Screenshots (`.compare/`): `orig-{light,dark}-*.png` / `port-{light,dark}-*.png` at 1440px and `orig-m-dark-*` / `port-m-dark-*` at 390px. Full-page heights: 1440 dark 3885 = 3885, 1440 light 3885 = 3885, 390 dark 5364 = 5364. Playwright position probe at 1440 (dark): sections start at 80 / 900 / 1812 / 2262 / 3020 / 3528, footer at 3796, accordion items at 3204 / 3261 / 3318 / 3375. These are identical in demo and port. Feature cards are 331×160 at x=208/555/901 in both.
- Interactive checks (`.compare/interact.mjs`): banner dismiss hides it; mobile Drawer opens (popup visible, right side, full height) and closes via the X; the accordion opens one item at a time and collapses on a second click; the theme menu sets Light (removes `.dark`, stores `light`, survives reload) and System; the locale menu "French" navigates to `/fr`; **no console errors**. The original's Sheet and theme menu were screenshotted for comparison (`orig-m-menu.png`, `orig-theme-menu.png` vs `port-m-menu.png`, `port-theme-menu.png`).
- Remaining differences:
  - The upstream banner is `fixed top-0` with no offset on the header, so it covers the top of the header (logo, Changelog/About, Login on desktop). On mobile it covers the menu trigger until dismissed. This is reproduced faithfully, not fixed.
  - The required "View original" button (`fixed bottom-4 right-4`) covers the footer theme toggle when scrolled to the very bottom at desktop widths. This is a conflict between the brief and this footer layout. The interaction test hides the button to reach the toggle.
  - Drawer width in headless mobile is 281px vs 292.5px (scroll-lock gutter; see Bugs). The Drawer close button has no focus ring on open, while Radix auto-focuses the close X and shows its ring.

## Lessons for a migration skill
- (General) Before styling anything, list the bejamas-juno defaults that differ from shadcn "default"/"new-york" and keep them in one override module (`src/lib/shadcn.ts` pattern: `shadcnButton.size.*`, `.variant.*`, `shadcnCard*`). Watch especially for `has-[>svg]:px-*` on Button, `md:text-xl` + `font-heading` on CardTitle, `text-sm` + `ring-1` + `py-6 gap-6` on Card, and `text-sm items-start` + muted icon on AccordionTrigger.
- (General) tailwind-merge only removes conflicting classes *with the same variant*. To override a component default that has a responsive or arbitrary variant (`md:text-xl`, `has-[>svg]:px-2.5`, `**:data-[slot=…]:text-…`), pass the same variant or style the inner element directly.
- (General) For a bordered shadcn card on bejamas 0.5.0, add `border-solid` (Card `border-none` bug).
- (General) Components that ship unlayered `<style is:global>` (Drawer) can't be resized with utilities. Use unlayered selectors with at least the same specificity in `globals.css`.
- (General, Tailwind v3 sites) Translate `container` from the actual config (center/padding/screens) into a custom utility. Re-check every `leading-*` combined with responsive `text-*`. Reproduce v3 gradient stop-reset semantics when `dark:from-*` is used without `dark:via-*`. Use v3 hex values for palette colors where exact color matters. Map v3 `shadow-sm` to v4 `shadow-xs`.
- (General) `next/font/local` without `weight` means weight 400, and `font-bold` on it is synthesized. Mirror that weight in `fontProviders.local()` variants, or the headings come out lighter.
- (General) Delete the template's `:root { --font-heading: var(--font-sans) }` once a dedicated heading font is configured.
- (General) Measure, don't eyeball. A Playwright probe that prints `getBoundingClientRect` for `main > section`, cards and accordion items in both demo and port caught the 6px line-height drift that screenshots hid.
- (General) "Loads in dark mode" may just be `defaultTheme="system"` on a dark OS. Check the ThemeProvider props, and replicate system behavior with an inline pre-paint script.
- (Site-specific) Session-dependent server components (Header, Pricing) render their signed-out branch. GitHub star counts become a build-time fetch with a fallback that matches the demo.
- (Site-specific) A fixed announcement bar overlapping the header is an upstream defect. Keep it for fidelity and record it rather than "fixing" it.
