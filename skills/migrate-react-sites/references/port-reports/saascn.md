# saascn migration findings

## Summary
- Source: https://github.com/techwithanirudh/shadcn-saas-landing @ `51027da3b5278cc632be59e893f67136ea3d919a`. Next.js 16.1.1, React 19.2, Tailwind v4.1.18 (`@import "tailwindcss"`, `@theme`, `@utility`), shadcn `new-york` / base color `zinc`, but the colour tokens actually come from `fumadocs-ui/css/neutral.css` + `preset.css` (the shadcn `--color-*` tokens are aliased to `--color-fd-*`). UI libs: fumadocs-ui `HomeLayout` (header, NavigationMenu, search dialog), Radix (accordion, avatar, dropdown-menu, tooltip), embla-carousel-react + `embla-carousel-auto-scroll`, `motion` (framer-motion), next-themes, lucide-react.
- Demo: https://saas-landing.techwithanirudh.com/
- Port: /tmp/bui-ports/saascn (preview port 4411)
- Fidelity verdict: **faithful** at 1440 / 768 / 390, light and dark. Remaining differences are documented approximations (Blog mega-menu and mobile menu float instead of pushing the header taller, search palette lists results before typing, minor font-rendering differences).
- Effort hotspots: (1) header: fumadocs `HomeLayout` nav (NavigationMenu + search + mobile menu) has no direct bejamas counterpart and had to be recomposed from three primitives; (2) testimonials carousel (autoplay timer, multiple visible slides, an Avatar-in-`<p>` parser bug); (3) recovering the real colour tokens, which live in fumadocs CSS rather than the repo's `globals.css`.

**Brief vs. source drift.** The orchestrator's notes mention a team section, pricing table with monthly/yearly tabs, contact form and a grain/gradient dark page. None of these exist on the home route in either the source (`src/app/(home)/page.tsx`) or the live demo: the home page is Hero → Customers (logo carousel) → Features → Testimonials → FAQ → CTA → Footer. The pricing tabs live on `/pricing`, the team on `/about` and the contact form on `/contact`, which are out of scope. The demo follows the **system** colour scheme (`defaultTheme='system'`), so it is light by default and dark only under `prefers-color-scheme: dark`; the port does the same. Because the pricing page is out of scope, the "derived-display price label listening to Tabs/Toggle" case was not exercised here. The same pattern was used instead for the theme toggle (Toggle → `toggle:change` → `.dark` class) and the search palette (Command → `command:select` → navigation).

## Component mapping (shadcn/React → bejamas/Astro)
| Source | Port | Notes on API differences |
|---|---|---|
| `<Button asChild><Link/></Button>` | `<Button as="a" href>` | bejamas Button defaults differ: `rounded-lg` (shadcn `rounded-md`), `sm` is `h-8.5 px-3 has-[>svg]:px-2` (shadcn `h-8 px-3 has-[>svg]:px-2.5`), `lg` is `px-5` (shadcn `px-6`), plus `active:scale-98` and `border-border` in the base. The outline variant has no `bg-background`. To match I added `rounded-md`, and `h-8 has-[>svg]:px-2.5` on the sm button. The `dark:bg-input/30` from the outline variant still wins over `bg-muted/70` in dark, exactly as in shadcn. |
| fumadocs `NavigationMenu` (Radix) with `asChild` header, `NavigationMenuViewport` inside the header | bejamas `NavigationMenu` + `NavigationMenuList/Item/Link/Trigger/Content` | No `asChild` and no "inline viewport" mode. The popup is always a floating, positioned `navigation-menu-positioner` (`side`/`align` relative to the trigger). `NavigationMenuTrigger` always renders a chevron SVG and defaults to `bg-background px-4 text-base font-medium`. I overrode it with classes and hid the chevron with `[&>svg]:hidden`. `NavigationMenuLink` adds `hover:bg-muted p-2 rounded-sm`, neutralised with `hover:bg-transparent`. |
| fumadocs mobile menu (`NavigationMenuTrigger` with ChevronDown, `NavigationMenuContent`) | `HamburgerMenu` + `HamburgerMenuItem` | HamburgerMenu renders its own bar (`h-12 px-3 border-b`). I used it as a compact trigger: `static w-auto` on the root lets the absolute panel (`inset-x-0 top-full`) anchor to the header container. Bar/panel padding, border and height are restyled via `[&_[data-slot=hamburger-menu-bar]]:…` / `[&_[data-slot=collapsible-content]]:…`, and `--hamburger-menu-panel-height:auto` stops it filling the viewport. |
| fumadocs search dialog (cmdk-like) | `Dialog` + `Command` composed manually (not `CommandDialog`) | `CommandDialog` puts its slot inside `DialogContent`, so a `DialogTrigger` can't be placed in it, which is why I composed it myself. `CommandInput` puts the search icon at the inline-end inside an `InputGroup`. The original has the icon at the start and an ESC kbd at the end, so I authored `<input data-slot="command-input" autofocus>` directly. Without `autofocus` the dialog focuses the Command root and typing goes nowhere. |
| `Accordion type="single" collapsible` | `Accordion` (default single, `collapsible` default true) | `AccordionItem` value is required. Open state styling: `aria-expanded:bg-card` instead of `data-[state=open]:bg-card`. `AccordionContent`'s `class` goes to the inner div, which matches shadcn. |
| `Carousel` (embla) with `setApi` + `useEffect` timer | `CarouselRoot` + `CarouselContent` + `CarouselSlide`, `data-loop`, `data-slides="multiple"` | No `opts`/plugins. `CarouselContent` defaults are `gap-4 rounded-lg` plus a focus ring offset, overridden to `gap-0 rounded-none`. shadcn's `-ml-4`/`pl-4` slide gutters don't exist. |
| `Avatar/AvatarImage/AvatarFallback` (Radix) | bejamas Avatar | Radix renders spans everywhere. bejamas `AvatarFallback` (and `AvatarImage` without `src`) render a `<div>` (see bugs). |
| Radix `DropdownMenu` + `DropdownMenuItem asChild><Link>` | bejamas DropdownMenu | `DropdownMenuItem` is a `div` with no `asChild`/`href`. I put an `<a>` inside the item (`class="p-0"`), so clicking works but keyboard Enter on the item doesn't follow the link. |
| next-themes `ThemeToggle mode="light-dark"` (button with sun+moon) | `Toggle` (`@data-slot/toggle`) | The pressed state is the dark theme. An inline script seeds `data-default-pressed` before the deferred primitive module reads it. `toggle:change` → `document.documentElement.classList.toggle("dark")` + `localStorage`. |
| fumadocs `kbd` hotkey hints | `Kbd` | bejamas Kbd defaults to `bg-muted h-5 text-xs font-medium` without a border. Overridden to `rounded-md border bg-background px-1.5 text-sm font-normal`. |

## Gaps in bejamas/ui (missing components, variants, props, primitives)
- **Carousel autoplay (testimonials)**: `@data-slot/carousel` has no autoplay or auto-scroll option. The section script only dispatches the documented `carousel:set {action:"next"}` command every 4s, re-arming on `carousel:change`. It pauses while the carousel is hovered or focused, or while the tab is hidden. It handles no focus, keyboard, pointer or ARIA. This is a borderline "block script" and a candidate for a primitive option (`data-autoplay`).
- **Carousel "multiple visible slides" isn't exposed by the bejamas component**: the primitive supports `data-slides="multiple"`, which keeps every intersecting slide active and non-inert. bejamas `Carousel`/`CarouselRoot` `variant="multiple"` only writes `data-variant` and turns each slide into a two-column grid, which is a different feature. I passed `data-slides="multiple"` through `...rest`. Without it, the second visible testimonial is `inert`/`aria-hidden`. Suggest a `slides` prop or renaming `variant`.
- **Continuous logo auto-scroll (embla AutoScroll, drag-free, pause on hover)**: replaced by `Marquee`. Marquee has no pause-on-hover option and no drag. Hover pause was added with `hover:[&_.marquee-content]:[animation-play-state:paused]`. Item widths given in `%` don't work inside Marquee (cyclic percentage: `.marquee-content` is shrink-to-fit). I used `@container` on the Marquee plus `w-[25cqw] md:w-[20cqw]` to reproduce embla's `basis-1/4 md:basis-1/5`.
- **NavigationMenu inline/full-width viewport**: fumadocs/Radix mount `NavigationMenuViewport` inside the header and let it push the layout. `@data-slot/navigation-menu` always positions a floating popup relative to the active trigger, with no "full width of root" alignment. The Blog panel therefore floats (with popover ring/shadow) instead of spanning the 1280px container.
- **HamburgerMenu**: no way to make the panel push content (it's `absolute top-full`), no trigger-icon slot (it's always menu/X), and no class props for the bar/panel. Everything had to be done with arbitrary descendant selectors from the root.
- **Dialog with more than one trigger / hotkey**: `@data-slot/dialog` binds a single `dialog-trigger` (`getPart`, not `getParts`) and has no keyboard-shortcut option. The mobile search icon and ⌘K/Ctrl+K dispatch `dialog:set {open:true}`.
- **Command item activation**: Command emits `command:select` but has no `href` on items. A listener does `location.href = value` (derived effect).
- **DropdownMenuItem as link**: no `asChild`/`href`. See the mapping table.
- **Search UX**: fumadocs shows no results until the user types. The Command primitive has no "hide list while the search is empty" attribute, so the port shows all 9 items on open.

## Bugs / issues in bejamas 0.5.0 or its CLI
- **Marquee keyframes are not installed.** `bunx bejamas add marquee -y` copies `src/ui/marquee/Marquee.astro`, which uses `[animation:marquee-x_…]`. Neither the scaffold's `src/styles/globals.css` nor `node_modules/bejamas/src/tailwind.css` defines `@keyframes marquee-x`/`marquee-y` (`grep -c "keyframes marquee-x" node_modules/bejamas/src/tailwind.css` → `0`). They only exist in the monorepo's `packages/ui/src/styles/globals.css`, and the `marquee` registry item has no `css` block. Observed: a static marquee. Expected: the keyframes are installed with the component. Workaround: I copied the two `@keyframes` into `globals.css` under `@layer theme`.
- **AvatarFallback renders `<div>` → broken DOM inside phrasing content.** The source puts `<Avatar>` inside `<p class="flex …">By <Avatar/> name</p>`. With bejamas, `<p><span data-slot=avatar><img/><div data-slot=avatar-fallback>` makes the HTML parser close the `<p>` (and the avatar `<span>`) at the `<div>`. The fallback (`absolute inset-0 bg-muted`) then positions against the slide and covers the whole testimonial card: the text disappears and a large "??" sits in the middle. Expected: inline-safe markup (`span`), as Radix does. Workaround: changed the wrapper `<p>` to `<div>`. The same applies to `AvatarImage` without `src` (it renders a `div`).
- **CLI template pin**: as the brief notes, the astro template pins `bejamas ^0.4.1`, so `bun add bejamas@0.5.0` is needed. The scaffold `Layout.astro` has no colour-scheme handling (no `.dark` class logic), although the tokens define `.dark`. Every site that follows the system theme needs its own head script.
- `CommandDialog` can't host a `DialogTrigger`: its slot renders inside `DialogContent`. Not strictly a bug, but it forces manual `Dialog` + `Command` composition for the common "search button opens palette" case.

## Theming, fonts, assets
- **Tokens**: the repo's `globals.css` only aliases `--color-*` to `--color-fd-*`. The real values come from `fumadocs-ui/css/neutral.css`, which isn't in the repo, so I read them from the live demo with `getComputedStyle(document.documentElement)` in both schemes (`.compare/vars.mjs`). Light: bg `#f5f5f5`, fg `#0a0a0a`, card `#f1f1f1`, popover `#fafafa`, primary `#171717`, secondary `#ededed`, muted-fg `#737373`, accent `#d1d1d180`, border `#cccccc80`, ring `#a3a3a3`. Dark: bg `#121212`, fg `#ebebeb`, card `#191919`, popover `#1e1e1e`, primary `#fafafa`, muted `#212121`, muted-fg `#b3b3b3cc`, accent `#6868684d`, border `#6663`. `--radius: .5rem`, destructive from the repo's `@theme`. They're written into `:root` and `.dark`, which replaces bejamas' blue `--primary`.
- **`.border-border` / `.divide-border` overrides**: the source redefines these utilities to 70% opacity in light mode (`@apply border-border/70 dark:border-border`). Redefining `.border-border` globally would also change bejamas components that use `border-border` (Button base, etc.). I added opt-in utilities instead (`border-soft`, `divide-soft`, `text-soft` via `@utility` with a `.dark &` branch) and used them wherever the source wrote `border-border`/`divide-border`. Measured colours match the demo: `oklab(… / 0.35)` for soft and `rgba(204,204,204,.5)` for default borders.
- **Other utilities**: the original `@utility container` (margin auto, padding 0, `2xl:max-w-[1400px]`) and `bg-dashed` hatch are copied as `@utility`. In Tailwind v4, re-declaring `@utility container` merges with the built-in breakpoints, which is the same as the source.
- **Fonts**: `next/font/google` Geist + Geist Mono, which I replaced with `fontProviders.google()` entries for `Geist` (`--font-sans`) and `Geist Mono` (`--font-mono`) with weights `100 900`, plus `<Font>` tags in the layout. `--font-mono` was added to `@theme inline`. The Google-served Geist wraps the CTA paragraph one word differently from the demo's next/font build (same 576px box). The ⌘ glyph falls back to a different font, so it's slightly larger.
- **Assets**: copied `public/images/gradient-noise-purple-azure-light.png`, `public/images/logos/{light,dark}/*.svg` and `src/app/icon.png` (favicon). Testimonial avatars (`https://github.com/<user>.png`) are downloaded into `public/avatars/` (96px) instead of hotlinked. The GitHub mark is inlined (lucide 1.x has no brand icons). BarChart3 is `ChartColumn` in `@lucide/astro`.
- **Dark mode**: an inline head script reproduces next-themes (`attribute="class"`, `defaultTheme="system"`): `localStorage.theme` or `prefers-color-scheme`, kept in sync with system changes.

## Animation & third-party libraries
- `motion` hero background fade (opacity 0→1, 0.4s): `motion-safe:animate-[hero-fade-in_0.4s_ease-out_both]` with a `@keyframes hero-fade-in` in `globals.css`.
- `embla-carousel-auto-scroll` (speed 0.6 px/frame ≈ 36 px/s): `Marquee time={20}` over a ~616px track (≈ 31 px/s), solid variant, no edge mask.
- Testimonials embla `scrollNext` timer: the primitive's `carousel:set` + native smooth scroll (`prefers-reduced-motion` handled by the primitive).
- Radix accordion height animation: bejamas accordion's own `animate-accordion-down/up`.
- `@bprogress/next` progress bar, React `ViewTransition`, the theme view-transition CSS, sonner and analytics were dropped (no visible effect on a static landing page).

## Next.js-specific translations
- `next/image` (hero PNG with `priority`, BlurImage logo/post wrapper) is now plain `<img>` with width/height, `fetchpriority="high"` for the hero and `loading="lazy"` for logos. BlurImage's blur-up placeholder is dropped.
- `next/link`/fumadocs `Link` became `<a>`. Secondary routes (`/about`, `/pricing`, `/contact`, `/blog/*`, `/tags/*`, `/newsletter`, `/privacy`, `/terms`, `/login`) point at the live demo URLs (`src/data/site.ts`). `env.NEXT_PUBLIC_APP_URL` resolves to `/login` on the demo.
- fumadocs-mdx `getSortedByDatePosts()`/`getTags()`: post frontmatter is copied into `src/data/site.ts` and sorted and deduplicated the same way, for the hero announcement link, the footer Posts/Tags columns and the search items.
- `ActiveLink`/`usePathname`: the home route is the only page, so "Home" is rendered as active statically.
- `createMetadata`/viewport `themeColor`: `<meta name="description">` and two `theme-color` metas in the layout.
- better-auth `useSession` in UserButton: signed-out state only ("Account" label + "Sign In").

## Lessons for a migration skill
- (General) **Read tokens from the running demo when the theme comes from a package** (fumadocs, a shadcn theme package, etc.): `getComputedStyle(document.documentElement).getPropertyValue('--color-fd-…')` in both `colorScheme`s is faster and more exact than chasing node_modules CSS.
- (General) **Never redefine a utility that bejamas components also use** (`.border-border`). Port such overrides as new opt-in utilities and apply them where the source used the class.
- (General) **Block elements inside `<p>`**: bejamas parts that render `div` (AvatarFallback, AvatarImage without src, many others) break when the source nests them in `<p>`/`<span>`. Grep the source for `<p` wrappers around components before porting. A missing-text symptom with a stray "??" fallback in the middle of a card is this bug.
- (General) **After `bejamas add`, grep the component for `animation:`/`animate-[…]` keyframe names and confirm the keyframes exist in your CSS** (Marquee needs `marquee-x`/`marquee-y`).
- (General) **Carousels with several visible slides**: pass `data-slides="multiple"` to `CarouselRoot`. bejamas' `variant="multiple"` is a different two-up grid layout.
- (General) **Percentage-width children in Marquee don't resolve**: use container query units (`@container` on the Marquee, `w-[25cqw]`).
- (General) **Search palettes**: compose `Dialog` + `Command` manually and put `autofocus` on the `data-slot="command-input"` element. The dialog focuses the first `[autofocus]` focusable, otherwise the Command root. Extra triggers and hotkeys go through `dialog:set`.
- (General) **HamburgerMenu as a compact trigger in an existing header**: `class="static w-auto …"` makes its absolute panel anchor to the nearest positioned header container. Restyle the internals with `[&_[data-slot=hamburger-menu-bar]]:…` and `[&_[data-slot=collapsible-content]]:…`, and set `--hamburger-menu-panel-height:auto`.
- (General) **Initial state of a primitive from client-only state** (theme, localStorage): set the `data-default-*` attribute from an inline script placed right after the element. It runs before the deferred module that creates the controller.
- (General) **Button size and radius drift**: bejamas Button is `rounded-lg` and uses different `sm`/`lg` paddings plus `active:scale-98`. Add `rounded-md` (and the height/padding fix for `sm`) when porting shadcn new-york buttons.
- (Site-specific) fumadocs `HomeLayout` sites: the nav is Radix NavigationMenu with an in-header viewport, which bejamas cannot reproduce. Budget for a floating panel and record it.
- (Process) Check the orchestrator's section list against `page.tsx` and the live home page before starting. Here half the listed sections belonged to other routes.
