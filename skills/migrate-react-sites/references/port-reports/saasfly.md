# saasfly migration findings

## Summary
- Source: https://github.com/nextify-limited/saasfly @ `49f7e28f69eae9cd9eed84221e13a3dbae87da67`, Next.js 14.2.5 (app router, `[lang]` i18n segment), Tailwind v3.4.1 (shared preset in `tooling/tailwind-config`), shadcn-style `packages/ui` (Radix "next" packages, `lucide-react` 0.323, cva). Landing-page effects are Aceternity / Magic UI copies on framer-motion 11: BackgroundLines, ColourfulText, AnimatedTooltip, ContainerScroll, GlowingEffect, AnimatedGradientText, Marquee. Runtime: next-themes (`defaultTheme="dark"`, `enableSystem={false}`), Clerk, tRPC.
- Demo: https://show.saasfly.io/en
- Port: /tmp/bui-ports/saasfly (port 4403)
- Fidelity verdict: **close, with documented approximations**. Section order, copy, assets, colors and spacing match: full-page heights are identical at 390px (3537), 1024px (3421) and 1440px (3369), and the opened mobile menu screenshot is pixel-identical to the original. The approximations are in motion: pointer-driven glow, tooltip spring, and colour shuffling.
- Effort hotspots: (1) framer-motion effects rebuilt in CSS (scroll-linked ContainerScroll, BackgroundLines path loop, ColourfulText); (2) Tailwind v3 runtime quirks that the source code does not reveal (unused Inter font, the `container` screens override, a dead `max-sm:px-4`, and utility classes Tailwind never generated); (3) three build/CSS traps: the minifier rewrote `animation-timeline`, `overflow-hidden` captured the view timeline, and v4 `space-y` met the inline `<script>`.

## Component mapping (shadcn/React → bejamas/Astro)
| Source | Port | Notes on API differences (props, asChild, variants, sizes, default classes) |
|---|---|---|
| `<Link><Button className=…/></Link>` | `<Button as="a" href target rel>` | The source nests a `<button>` in an `<a>`. The port uses a single anchor. bejamas sizes differ: `sm` is `h-8.5` (shadcn `h-9`), the default is `h-9` (shadcn `h-10`), and the radius is `rounded-lg` (shadcn `rounded-md`). Pass `h-9 rounded-md` to match. bejamas adds `shadow-xs` and `active:scale-98`; the port removes the shadow with `shadow-none`. |
| shadcn Button `[&_svg]:size-4` | bejamas `[&_svg:not([class*='size-'])]:size-4` | Semantic difference. In shadcn the descendant selector beats `h-5 w-5` on the icon, so the demo's "Get Started" arrow renders at 16px. bejamas respects an explicit `size-*`. The port passes `size-4` to reproduce the runtime size, not the source class. |
| Button `variant="outline"` (Login) | Button `variant="outline"` plus overrides | bejamas outline in dark mode is `dark:bg-input/30 dark:border-input dark:hover:bg-input/50` with `hover:border-accent`. shadcn's is `border-input bg-background hover:bg-accent`. Overrides: `bg-background dark:bg-background hover:bg-accent hover:border-input dark:hover:bg-accent`. |
| Button `variant="ghost"` (icon triggers) | `DropdownMenuTrigger variant="ghost"` | bejamas ghost hover is `bg-secondary`; shadcn's is `bg-accent`. Override with `hover:bg-accent hover:text-accent-foreground`. |
| `Card` (`rounded-lg border bg-card shadow-sm`) | `Card` | bejamas Card adds `py-6 gap-6 ring-1 ring-foreground/10 shadow-sm shadow-lg overflow-hidden rounded-xl text-sm`, and contains both `border-none` and `border border-border`. **A passed `border` renders nothing because `border-style: none` wins.** Add `border-solid`. Needed: `gap-0 p-3 ring-0 shadow-xs text-base border border-solid rounded-3xl`. |
| Radix `DropdownMenu` + `DropdownMenuItem onClick` | `DropdownMenu` + `DropdownMenuItem value=…` and a listener for the `dropdown-menu:select` event | No per-item onClick. Read `event.detail.value` / `detail.item` on the root. Content is **portalled**: items are no longer descendants of the root, so tests must query `[data-slot=dropdown-menu-item]` globally. The content defaults to `w-[var(--anchor-width)]` (32px for an icon trigger); pass `w-auto min-w-[8rem]`. It also uses `ring-1 rounded-lg` where shadcn has `border rounded-md`. |
| Aceternity `AnimatedTooltip` (framer `AnimatePresence`) | `Tooltip delay={0}` / `TooltipTrigger asChild` / `TooltipContent` | Restyled with `bg-black px-4 py-2 rounded-md flex-col` and the arrow hidden via `[&>[data-slot=tooltip-arrow]]:hidden`. The trigger with `asChild` wraps the child in a `div[data-slot=tooltip-trigger]`. |
| Magic UI `Marquee` (`repeat=4`, `pauseOnHover`, `reverse`, `[--duration]`, `[--gap]`) | `Marquee direction time variant` | Only two copies, each `min-w-full justify-around whitespace-nowrap`, with no gap or pause prop. Recipe: `[&_.marquee-content]:min-w-max justify-start gap-4 pr-4 whitespace-normal`, `hover:[&_.marquee-content]:[animation-play-state:paused]`. Repeat the items inside the slot so one copy is wider than the viewport, and scale `time` to keep the speed (80s for 2×3 cards of 256px ≈ the source's 20px/s). Use `variant="solid"` when the source draws its own edge fades. |
| `useScroll` sticky header | `StickySurface` | Its classes are `sticky top-0 z-50 … will-change-transform`. Override `z-40`, and the line colour (`after:bg-black/15`, invisible in dark mode) with `after:bg-border`. `will-change-transform` and `backdrop-blur` both make the header the containing block for fixed descendants, which matches the source's fixed mobile panel. |
| `useState` mobile toggle | `Collapsible` | Swap the trigger icons with `group-aria-expanded/menu:` (the primitive sets `aria-expanded`). The content's `grid` class does not fight the closed state, because preflight's `[hidden]` uses `!important`. |

## Gaps in bejamas/ui (missing components, variants, props, primitives)
- **HamburgerMenu composition is fixed**: the brand slot sits on the left, and the actions plus a built-in hamburger/X trigger sit on the right. Saasfly's mobile bar puts a custom "⌘ Menu" trigger on the left and Login/Sign up on the right. The port uses Collapsible directly. HamburgerMenu would need a trigger slot or a trigger position option.
- **Collapsible has no "close on link click" or scroll lock**. HamburgerMenu has close-on-link-click internally, but plain Collapsible does not. A same-page `#features` link leaves the panel open, and `useLockBody` was dropped.
- **Marquee**: no `pauseOnHover`, `gap` or `repeat` props, and only two copies (see mapping). `whitespace-nowrap` on the copies breaks wrapping card text unless it is overridden.
- **Pointer-tracking effects**: GlowingEffect (border glow following the pointer angle) and AnimatedTooltip's spring (rotation/translation following the pointer) have no primitive. The port uses a CSS hover approximation for the glow and drops the spring.
- **Clipboard copy**: no primitive. `CodeCopy.astro` has a tiny click → `navigator.clipboard.writeText` script that toggles a `data-copied` attribute for the icon swap. It manages no menu, dialog or toggle state.
- **Theme switching**: no theme primitive. A `dropdown-menu:select` listener sets the `.dark` class and `localStorage`, and an inline head script restores the choice before paint (next-themes equivalent).
- **Sign-up modal** (`ModalProvider` / `useSigninModal`): auth is out of scope. Sign up and Login link to the demo's `/en/login-clerk`.

## Bugs / issues in bejamas 0.5.0 or its CLI
- **Marquee does not animate in a fresh 0.5.0 Astro project.** `Marquee.astro` uses `[animation:marquee-x_var(--duration,_20s)…]`, but `@keyframes marquee-x` and `marquee-y` exist in neither `node_modules/bejamas/src/tailwind.css` nor the scaffolded `src/styles/globals.css`. In the monorepo they live only in `packages/ui/src/styles/globals.css` (`@layer theme`). Repro: `bejamas init -t astro`, then `bejamas add marquee` and render one; the transform stays `none`. The port adds both keyframes to `globals.css`. Expected: the keyframes ship with the component or in `bejamas/tailwind.css`.
- **Card `border-none` plus `border border-border`** in the same class string: the border can never be turned on without `border-solid` (see mapping). The class list also includes both `shadow-sm` and `shadow-lg`.
- **Scaffold template** writes `<html  lang="en">` (double space), links a `/favicon.svg` and `/bejamas.svg` that a port must replace, and has `--font-heading: var(--font-sans)` in `:root` while `@theme inline` declares `--font-sans: var(--font-sans)`, which is self-referential. If no `<Font cssVariable="--font-sans">` is rendered, `:root` must define `--font-sans` itself, as this port does.
- **StickySurface** default line colour `after:bg-black/15` is invisible on dark themes. `effects` has no colour prop; override with `after:bg-border`.

## Theming, fonts, assets
- **Tokens**: the HSL triplets from `apps/nextjs/src/styles/globals.css` are wrapped in `hsl()` for Tailwind v4, covering `:root` and `.dark` (background `240 10% 3.9%`, card `224 71% 4%`, primary `210 40% 98%`, and so on). `--radius: 0.5rem`, so `rounded-md` resolves to 6px as in v3. bejamas' blue `--primary` and its oklch neutrals are fully replaced. The source has no chart or sidebar tokens; chart tokens got shadcn defaults and sidebar tokens were removed.
- **Fonts, a source vs runtime drift**: `layout.tsx` loads Inter via `next/font/google` into `--font-sans` and CalSans into `--font-heading`, but the Tailwind preset never sets `fontFamily.sans: var(--font-sans)`. The demo therefore renders **Tailwind's default `ui-sans-serif, system-ui` stack**, confirmed with `getComputedStyle` on the live page. The port reproduces the runtime: `--font-sans` and `--font-mono` are set to the Tailwind default stacks in `:root`, no Google font is loaded, and CalSans is loaded with `fontProviders.local()` as `--font-heading` (unused on the landing page, as in the source).
- **`container`**: the v3 preset has `container: { center: true, padding: "2rem", screens: { "2xl": "1400px" } }`. A `screens` key *replaces* the container breakpoints, so the container is fluid below 1400px and capped at 1400px. The first attempt used the default v3 breakpoints and the content was 120px narrower at 1440px. It is reproduced with `@utility container`. The source's `.container { @apply max-sm:px-4 }` sits in `@layer base` and loses to the components-layer padding, so it is dead in the demo: the mobile gutter is 32px, not 16px. Mirroring it caused a visible mobile diff until it was removed.
- **Classes Tailwind never generated** in the source (`rounded-2.5xl`, `border-0.75`, `-tracking-4` in `rightside-marketing.tsx`, and `animate-gradient`) render as no-ops in the demo, so the port omits them rather than "fixing" them.
- **v3 → v4 details**: `bg-gradient-to-*` became `bg-linear-to-*`. v3 `shadow-sm` equals v4 `shadow-xs`. Palette colours are oklch in v4 (for example `neutral-800`), which is visually identical here. With v4 `space-y-*`, all children except the last get `margin-block-end`, while v3 used `~` sibling `margin-top`. Astro inlines a component's processed `<script>` next to its markup, so `<CodeCopy/>` (div plus script) left the div with an extra 16px bottom margin in a `space-y-4` column. The port replaced `space-y-4 sm:space-x-8` with `gap-4 sm:gap-8`.
- **Assets**: `logo.svg` (favicon), `favicon.ico`, `images/clerk.png` and `images/avatars/saasfly-logo.svg` were copied from `public/`. Downloaded from their remote URLs: the six GitHub avatars, the six `avatar.vercel.sh` gradients (served as PNG despite the URL), two sponsor logos, and the video cover from `cdnv2.ruguoapp.com`. The cover goes through `astro:assets` `<Image>` (992kB PNG → 47kB WebP), the equivalent of `next/image`. Nothing is hotlinked.
- **Default mode**: `<html class="dark" style="color-scheme: dark">`, with an inline head script that restores `localStorage.theme` (`light`, `dark` or `system`).

## Animation & third-party libraries
- **BackgroundLines** (framer `motion.path` × 42): CSS keyframes per path. CSS has no `repeatDelay`, so one keyframe set is generated per repeat delay (2–11s), with the 10s motion compressed into the first `10/(10+rd)` of the cycle. The delays are randomised at build time with the source's distributions. Lesson: `animation-fill-mode: backwards` is needed. Without it, every path showed its "initial" dash during the delay and clustered near the SVG centre; the demo shows nothing until each path starts. The non-positioned wrapper is preserved on purpose: the absolute SVG resolves against the initial containing block (the first viewport), exactly as in the demo.
- **ColourfulText**: the React version reshuffles the palette at random every 5s and replays a 0.5s blur/lift per letter. The port cycles each letter through the same 10 colours every 5s (offset per letter, so frame 0 equals the unshuffled React render) and replays the blur pulse every 5s with a 50ms stagger. This is a rotation, not a random shuffle. Each letter stays an `inline-block`, so "Saasfly" wraps mid-word at 1024px, exactly like the demo ("Sa|asfly").
- **ContainerScroll** (framer `useScroll({ target })`, default offset `start start` → `end end`): `view-timeline-name` on the 80rem container, and `animation-range: contain 0% contain 100%` on the card and header. Keyframes are `scale(1.05) rotateX(20deg)` → `scale(1) rotateX(0)` (scale 0.7 → 0.9 at ≤768px), and title `translateY(0 → -100px)`. Framer applies scale before rotate, and that order matters for the matrix. Two traps:
  1. The build's CSS minifier folded `animation: name linear both` plus `animation-timeline: --x` into `animation: linear both name --x`. That declaration is invalid because `animation-timeline` is reset-only in the shorthand, so the whole animation was dropped. **Use longhands** (`animation-name`, `animation-timing-function`, `animation-fill-mode`, `animation-timeline`).
  2. The source wrapper's `overflow-hidden` makes it a scroll container, so the view timeline resolved against an element that never scrolls and stayed stuck at 100%. **Use `overflow-clip`**, which clips without creating a scroll container.
  Without `animation-timeline` support, the flat end state is shown.
- **GlowingEffect**: framer `animate()` of `--start` toward the pointer angle became an `@property --glow-start` orbit animation on `:hover` and `:focus-within`, keeping the source's gradient and conic mask. This is a documented approximation.
- **AnimatedTooltip**: the spring entrance and pointer-driven rotate/translate were dropped. The Tooltip's own zoom and slide-in animation is used.
- **Marquee**: the CSS-only Magic UI version maps to bejamas Marquee (see mapping). Reduced motion: every CSS animation added in the port has a `prefers-reduced-motion` fallback.

## Next.js-specific translations
- `next/image` with remote URLs → files downloaded into `public/`, and `astro:assets` `<Image>` for the large cover. Plain `<img>` with the source's `width`/`height` for avatars and logos.
- `next/link` → `<a>`. Locale-prefixed internal routes (`/${lang}/pricing`, `/blog`, `/docs`, `/login-clerk`) point at `https://show.saasfly.io/en/...`. `/#features` became `#features`; no element has that id in the source either.
- `next/font` → Astro fonts API (only CalSans, see Theming).
- `next-themes` → `.dark` class plus inline restore script plus a `dropdown-menu:select` handler.
- i18n (`[lang]` segment, `getDictionary`, middleware redirect): the English dictionary `config/dictionaries/en.json` is copied to `src/data/en.json` and imported at build time. LocaleChange's other locales navigate to the demo's `/zh`, `/ko` and `/ja`.
- Server components and `getCurrentUser()`: the page is fully static and rendered as signed-out (Login and Sign up visible), as the demo shows.
- `metadata` → `<title>Saasfly</title>`, description and OG tags in `Layout.astro`, with favicon `logo.svg`.
- Vercel Analytics, SpeedInsights, Toaster, TailwindIndicator, ClerkProvider and NextDevtoolsProvider were dropped.

## Lessons for a migration skill
- **(General) Probe the live demo's computed styles before mapping fonts and containers.** `next/font` variables are often loaded but never wired into `tailwind.config` `fontFamily`. The runtime font is then the Tailwind default stack, and loading the "declared" font makes the port *less* faithful.
- **(General) The Tailwind v3 `container.screens` key replaces the breakpoints**: one `2xl` entry means fluid up to that width. Rebuild it with `@utility container`. Also check which `@layer` any `.container` override sits in; a `@layer base` override loses to the plugin.
- **(General) Classes that never existed in the source's Tailwind config are no-ops at runtime.** Don't "fix" them into real v4 utilities (`rounded-2.5xl`, `border-0.75`, `-tracking-N`, an `animate-*` without keyframes).
- **(General) Scroll-driven CSS in Astro builds**: write `animation-*` longhands whenever `animation-timeline` is involved, because the minifier merges a shorthand into an invalid declaration. Replace `overflow-hidden` ancestors with `overflow-clip`, or the view timeline binds to the wrong scroller. framer `useScroll({target})` maps to `animation-range: contain 0% contain 100%`.
- **(General) v4 `space-x/y` plus Astro inline `<script>`**: a component that renders markup plus a script can become "not last child" and pick up the spacing margin. Prefer `gap-*` in flex containers that hold scripted components.
- **(General) Aceternity path loops**: emulate framer `repeatDelay` with per-delay keyframes and `fill-mode: backwards`. Keep the source's non-positioned wrappers when the effect relies on the initial containing block.
- **(General) shadcn `[&_svg]:size-4` overrides icon `h-5 w-5` at runtime; bejamas does not.** Match the rendered size, not the class.
- **(bejamas-specific) Add the `marquee-x`/`marquee-y` keyframes** to `globals.css` until the package ships them. For the Card, always add `border-solid` and `ring-0` when the source uses a plain bordered card. For DropdownMenuContent, add `w-auto min-w-[8rem]` on icon triggers, and remember the content is portalled when writing tests or listeners (listen on the root, query items globally).
- **(bejamas-specific) HamburgerMenu's fixed bar** doesn't fit nav bars with a left-side custom trigger. Use Collapsible with `group-aria-expanded:` icon swaps.
- **(General, tooling)** The session scratchpad can be shared between parallel agents. Write comparison screenshots straight into the port's `.compare/`, never into a shared temp folder, or another site's shots can overwrite or contaminate yours.
